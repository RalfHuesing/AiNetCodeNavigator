# M2-T1.6 — Indexscope und Projektidentität belegen

[Roadmap index and status](../roadmap.md) · [Parent scope and historical evidence](M2-T1.md) · [Execution and evidence rules](../roadmap.md#ausführung-und-nachweise) · [Approved concept](../Konzept.md)

**Intention:** Den tatsächlich geladenen Source-Scope einschließlich Identität, Framework-Kontexten und Ausschlüssen nachvollziehbar machen.

**Scope:** `get_index_scope`, zugehörige Inventar-/Identitätsprojektionen, SDK-Schema und Verbraucher gegen Muss 3/12 prüfen und vervollständigen. Stabile kanonische Projektidentität, tatsächlich geladene Framework-Kontexte sowie ausgeschlossene Dokumente und nicht analysierte konfigurierte Frameworks getrennt belegen. Begrenzte ermittelte Indexlisten verwenden deterministisches `resultCursor`-Paging und positives `maxResults` als Seitengröße; Filter gelten vor Totals/Paging.

**Nicht:** Keine Analyse aller Target Frameworks, keine Assembly-Ersatzroute für das Source-only-Tool und kein neues Projekt-/Refreshwerkzeug.

**Abnahme:** Eigenständige Fixtures belegen stabile Projektidentität bei separatem Runtime-Reload, geladenes Framework, nicht analysierte Frameworks und Dokumentausschlüsse. Das Inventar wird bei mehr Einträgen als Seitengröße exakt einmal rekonstruiert. Query-/Snapshotbindung, äußere Seiten, ungültige/veraltete Cursor und Targetänderungen sind belegt. Ein früherer fokussierter grüner Indexscope-Test ersetzt keine aktuelle Prüfung der vollständigen betroffenen Klasse.

**Verifikation:** Offizieller Build und engste betroffene Scope-/Workspace-Fast-/Integrationsauswahl, einschließlich aktueller `IndexScopeContractTests`. Relevante Extended-Workspacefälle gezielt nach Repository-Regeln auswählen. Aktuelle Indexscope-/Framework-/Ausschlussdokumentation im selben Slice prüfen.

## Abschlussnachweis

- `get_index_scope` uses the loaded solution snapshot's evaluated MSBuild framework metadata. The index-scope snapshot ID and inventory cursor include that metadata, so a project configuration change invalidates an earlier result cursor even when the loaded framework context remains the same.
- The independent SDK fixture loads `net10.0` from a `net10.0;net9.0` project and reports `net9.0` as configured but unanalyzed. A second runtime preserves canonical project identities. Four projects with two documents each produce eight document entries, four generated documents excluded from default symbol search, and five inventory entries in deterministic order; page size two reconstructs them exactly once.
- The cursor fixture reproduced a missing query binding: after page size two, the cursor was accepted at page size three. The public route now returns `RESULT_CURSOR_ARGUMENT_MISMATCH`; a different target returns the same code, and changed source or framework metadata returns `STALE_SNAPSHOT`. Outer pages still reconstruct under changed response budgets.
- A FastTests fixture with two loaded framework contexts for the same canonical project path confirms neither loaded context is reported as unanalyzed; one remaining configured framework is reported. In-memory projects expose `configuredFrameworksKnown=false`, so unavailable project metadata is not presented as an empty evaluated configuration.
- Checks run: `pwsh -File ./scripts/build.ps1` passed with 0 warnings/errors; `pwsh -File ./scripts/test-fast.ps1 -Filter "FullyQualifiedName~IndexScopeScannerTests"` passed 11/11; `pwsh -File ./scripts/test-integration.ps1 -Filter "FullyQualifiedName~IndexScopeContractTests"` passed 1/1; and `pwsh -File ./scripts/test-integration.ps1 -IncludeExtended -Filter "FullyQualifiedName~MSBuildSolutionLoader_"` passed 5/5, including both relevant ExtendedIntegration workspace-loader tests.
- The deployed Navigator MCP returned its older report shape during the source-only query; source and current checked-out tests remain the verification authority for this slice.
