# M3 — Discovery and metadata ownership

## Intent and scope

Improve declaration discovery and source-to-metadata transitions with exact ownership. Implements P3 and [concept 5.4–5.5](../concept.md#54-type-relationships-and-metadata-contracts). Depends on M2; ends with twelve public tools.

## Executable points

- [x] **M3.1 — Integrate extension declarations and discovery filters.** Extend `find_symbol` for source/assembly extensions, project/namespace/signature filters, and declared receiver matching. Preserve existing discovery/batching and old extension-search capability. Migrate regressions and consumers/docs; remove `find_assembly_extensions` after replacement checks pass. Acceptance: filtered results retain actual extension status, correct owners and usable references; ineffective/invalid argument combinations fail; no expression-applicability promise.
- [ ] **M3.2 — Resolve metadata contracts in source type relationships.** Use existing loaded compilation/reference facts for qualified metadata types and exact member IDs, including explicit validated metadata-owner selection. Preserve source-first resolution and ambiguity semantics. Acceptance: BCL/interface-member implementations and overrides bind semantically; duplicate owners do not get guessed; returned source/assembly references support exact owner-qualified follow-ups; arbitrary DLL paths are not loaded by this selector.
  - [x] **M3.2a — Establish exact metadata resolution and owner evidence.** Reuse captured immutable reference facts and pass them through the request-lived source context. Resolve supported raw type/member identifiers across loaded compilations, retaining bound contract occurrences, proven path/image/declaration identities, ambiguity and validated owner selection. Verify these Core behaviors with small existing fixture builders; do not expose the incomplete MCP capability yet.
  - [ ] **M3.2b — Integrate image-safe relationships and the MCP contract.** Use the validated occurrences for semantic hierarchy/implementations, including transitive source project relationships and event mappings, without merging distinct images with equal assembly identities. Complete source-first routing, root/implementation ownership, options/cursors/recovery, current documentation, targeted integration/extended checks and W5 Exploration follow-ups.
- [ ] **M3.R — Independent Sol review, fixes, and acceptance.** Review filter comparison behavior, source-first/metadata fallback, overload/owner mapping, assembly closure limitations, advertised follow-ups, and twelve-tool catalog. Close after required fixes/checks pass.

## Verification and non-goals

No new metadata index, arbitrary reference closure, expression completion, dynamic dispatch simulation, or owner-reference grammar change.

### M3.2 execution boundary

Before production edits, the Sol implementation agent identified that the existing hierarchy/implementation paths use solution-wide `SymbolFinder`. A selected metadata seed followed by a simple project filter cannot safely distinguish competing images with equal Roslyn assembly identities, including contracts reached through source project references. M3.2 is therefore split into exact request-lived resolution/evidence and its image-safe relationship/MCP consumers. The children preserve the complete concept contract and the existing Core/MCP boundary; no extra milestone, persistent index or new public tool is introduced. Both children and independent review are required before M3 acceptance.
