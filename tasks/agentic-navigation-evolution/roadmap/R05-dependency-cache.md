### Concrete API/lifetime decisions during implementation

Core owns one typed DependencyGraphCache instantiated/disposed by NavigatorHostRuntime, using the existing .NET cancellation, synchronization and TimeProvider primitives. The existing scanner supplies per-document immutable scalar facts and the shared merge/projector. Source calls pass the already validated private snapshot ticket plus canonical target/scope/generated selection; direct Core and assembly calls remain uncached. Visible cached endpoints use scalar documentation declaration IDs and exact owner/context resolution in the current request Solution, including endpoints outside originating collection filters. Formatting and Roslyn objects are never retained in buckets. This narrow helper is required because cached scalar facts must preserve visible owner-bound navigation without retaining ISymbol or formatting hidden result pages.

The consumer identifies a concrete registry race: after removal under its gate but before outside-lock path-only cleanup, another Lease of the same target can publish a fresh resident and cache job. Path-only retirement would cancel new-owner work. Root selects the smaller existing-ticket boundary: each live registry entry records its maximum validated SnapshotTicket after successful freshness/identity and before handler work; actual retirement signals canonical target plus that ticket cutoff. Cache cleanup touches only that target's tickets at or below the old-owner cutoff; later monotonic tickets remain valid. A never-analyzed owner has cutoff zero. No permanent target tombstone, extra cache key dimension, new owner-generation framework or blocked-load fence is introduced.

This race is caught while the initial R05 cache API is still being implemented and is not yet an executable completed product path; no failing executed cache baseline is claimed. Workers must supply a deterministic focused retirement-race acceptance test before the final R05 gate. Ordinary retention eviction remains independent from in-flight jobs, while actual retired-owner jobs may be cancelled/drained outside locks. Root records these extensions because their concrete forcing requirements are visible navigation and safe source-owner cleanup, not hypothetical general reuse.
