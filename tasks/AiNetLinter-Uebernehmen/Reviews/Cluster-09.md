## Point 9.1 implementation record

- Implementation base: `9470613a57951cb5085c800ee15ce69c110948c0` (clean working tree at handoff); implementer model `gpt-6-luna`, high reasoning. This is an implementation record, not the independent point audit. Audit 1/3 is pending; the 9.1 parent point remains unchecked until that review.
- `Program.Main(args)` now invokes a `System.CommandLine` root command and the Generic Host. The stdio SDK registration attaches the argument validation filter and the two implemented maintenance tools. `InvocationConfiguration` sends help and parse errors to stderr. Logging uses the existing rolling-file/error-stderr Serilog setup, bridged into Generic Host after clearing default providers; stdout is used only by MCP transport.
- `get_server_health` reports uptime, resident/loading source solutions, resident assembly sessions and active accesses, handoff handles, compilation-cache counters, managed memory, settings version, and minimum log level. An optional supported absolute target path is checked against current registry snapshots and reports resident state without acquiring or refreshing a target. `AssemblyAnalysisSessionRegistry.GetHealthSnapshot` is a read-only metadata snapshot. No compiler or assembly diagnostic samples are exposed.
- `reload_config` reads `--config <path>` or `%LOCALAPPDATA%/AiNetCodeNavigator/hostsettings.json`. A missing default file uses built-in `Information` logging; an explicit missing file fails startup, and a missing file on explicit reload returns `CONFIG_NOT_FOUND`. JSON accepts only `minimumLogLevel` with exact values `Verbose`, `Debug`, `Information`, `Warning`, `Error`, and `Fatal`; malformed JSON, duplicate/unknown fields, and other values fail without changing the active version or log switch. Successful publication is serialized under one state gate and increments an immutable settings version. No file watcher is registered and the tool does not write the settings file.
- The supported runtime setting is deliberately limited to log level. Response budgets, response windows, registry capacities/TTLs, transport, and log paths stay fixed for the running host. This avoids swapping resident registries or operation stores while calls may hold leases. `LongRunningToolCallStore` uses the AiNetLinter-compatible 15-second response window and links cancellation to `IHostApplicationLifetime.ApplicationStopping`. `NavigatorHostRuntime` drains the operation store before disposing project and assembly registries.
- Dependency fit was verified against official sources: [Model Context Protocol C# SDK stdio transport](https://github.com/modelcontextprotocol/csharp-sdk/blob/main/docs/concepts/transports/transports.md), [Microsoft.Extensions.Hosting 10.0.12](https://www.nuget.org/packages/Microsoft.Extensions.Hosting/10.0.12) (stable, MIT, compatible with net10.0; package dependency minimum DI/Abstractions 10.0.12), and [System.CommandLine documentation](https://learn.microsoft.com/dotnet/standard/commandline/). The repository's existing DI pins were aligned to 10.0.12; System.CommandLine 2.0.11 was already pinned and remains unchanged. `dotnet list AiNetCodeNavigator.slnx package --vulnerable --include-transitive` reported no vulnerable packages from the configured sources.
- FastTests cover atomic valid configuration publication, exact enum/field validation, failed reload preservation, missing default configuration, and ApplicationStopping cancellation of an active operation. Both maintenance tools expose the same public response controls: `maxResponseBytes` 512–65,536 (default 16,384) and optional positive `maxResponseTokens`; they apply to success and recoverable errors. A token cap too small for the required result produces a sanitized JSON-RPC `InvalidParams` error.
