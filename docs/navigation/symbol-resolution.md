# Shared Symbol Resolution

The existing `handoffId`, `fromHandoffId`, and `toHandoffId` fields carry stable declaration references; JSON field names, casing, null behavior, and renderer formats remain the same. `docCommentId` remains descriptive metadata, and there is no second stable-ID field. Source references have the form `src:<project-path>|<declaration-id>`; assembly references have the form `asm:<simple-name>|<declaration-id>`. The codec escapes `%`, `|`, and ASCII spaces as `%25`, `%7C`, and `%20`, and decodes those escapes once. References identify declarations, not snapshots or historical entities.

For source, `<project-path>` is the canonical relative path of a loaded project from the nearest `.git` working-directory root, or from the selected solution directory when no Git marker exists. The declaration ID is the exact Roslyn documentation declaration ID. Resolution selects that loaded project first and then requires one exact declaration-ID round-trip in its current compilation. If the same physical project path identifies multiple loaded Roslyn contexts, resolution returns `AMBIGUOUS_SYMBOL` and reports the owner path, project name, target framework, configuration, and platform for each context. Recovery uses a solution/load configuration with one intended context; this wire reference does not add a TFM or candidate-ID selector. For assemblies, the simple name comes from metadata and resolution occurs only in the supplied target assembly's current owner generation. Keep the exact returned `targetPath`/`ownerTargetPath` with an assembly reference, especially when a result belongs to a referenced DLL. An evicted owner is reopened through normal target loading. Selecting a different same-name DLL deliberately selects that target.

The source `snapshotId` in navigation analysis metadata represents the full binding inputs for the loaded solution; it is separate from the declaration reference. The versioned `source-analysis-v1` fingerprint covers the canonical solution and project coordinates, loaded project and compiler options, source/additional/analyzer-config/generated document contents, captured analyzer or provider inputs, project-reference edges, and immutable metadata module image hashes. Source generators are admitted only when their actual creating owner supplies an internal immutable input contract bound to the exact project, analyzer path, emitted image bytes, and effective binding inputs. The loader recaptures and matches those inputs at every fresh boundary, then binds generated source from the captured image. A normal MSBuild origin, rooted path, static assembly-reference closure, or lack of an observed load failure does not establish creator proof. Built-in SDK source generators also require an explicit producer contract; MSBuild discovery alone does not admit them. When no supplied contract matches the captured inputs, navigation returns `WORKSPACE_DIAGNOSTIC` before identity reuse. A changed image with a matching contract creates fresh references and a new snapshot. Analyzers that navigation does not execute are not treated as source generators. Records use canonical ordering, so equivalent loaded inputs have the same content identity. A source request first asks the resident workspace to refresh disk-backed source, project, and referenced-image evidence, then computes or reuses the identity for the resulting immutable Roslyn `Solution`. A same-timestamp content replacement is therefore eligible to produce a fresh binding snapshot. The runtime memo is weakly keyed by that exact `Solution` object and retains scalar fingerprint data; project markers and the exact declaration-reference formatter are rebuilt for each request instead of retaining Roslyn projects, compilations, or symbol references. A reloaded but equivalent solution can have the same deterministic content identity while remaining a distinct memo entry.

Identity is published only when the workspace owner can account for the binding inputs. Normal MSBuild-loaded projects use the loader's captured provenance. TestKit-built projects use the builder's exact-output proof; custom in-memory metadata references need creator-supplied immutable PE/module bytes, and custom XML documentation needs creator-supplied XML bytes. Physical PE references use their adjacent XML sidecar when present. An arbitrary external Roslyn `Solution` or opaque custom provider is not accepted merely because its current values can be inspected; missing creator evidence returns `WORKSPACE_DIAGNOSTIC` instead of a partial fingerprint.

Identity requires loaded C# projects with Roslyn's supported `CSharpParseOptions` and `CSharpCompilationOptions` values. Roslyn 5.9 seals both option classes, so the supported public API cannot supply derived option subtypes. Roslyn also fills omitted option sets when a `ProjectInfo` is added to a solution; the missing-options guard is defensive and is not reachable through that public construction path. When compilation options are applied to a workspace project, Roslyn may substitute its loaded syntax-tree options provider; the encoder requires creator provenance for the provider actually present in the resulting project. Unsupported languages and untracked binding inputs return `WORKSPACE_DIAGNOSTIC` rather than producing a partial identity.

Roslyn's `AssemblyIdentityComparer` constructor is internal, so external callers cannot supply an unrecognized comparer through the public API. The encoder still fails closed if an internally supplied comparer is neither the default comparer nor the supported desktop comparer.

An unchanged declaration reference remains usable after body edits, unrelated edits, project-option changes, or a server restart when the same owner coordinate and declaration ID still select exactly one declaration. A rename, signature change, project move, or missing declaration requires fresh discovery. Retained response pages and analysis evidence remain tied to their reported snapshots; assembly relationship work also retains its existing generation leases and owner provenance. Body windows resolve the current declaration text. Do not combine windows read from different reported snapshots as one body.

Input routing examines the original argument before the normal discovery-name cleanup. For a reference, the resolver trims only outer ASCII spaces, strips at most one matching enclosing pair of backticks, double quotes, or single quotes, trims outer ASCII spaces again, then validates the remaining payload. It does not normalize the path or declaration ID. Prefixes are recognized case-insensitively for routing, while canonical wire prefixes are lowercase. A reference has one unescaped `|`, two non-empty components, uppercase canonical escapes, and a declaration ID beginning with `T:`, `M:`, `P:`, `F:`, or `E:` followed by a non-empty value. Only `%`, `|`, and ASCII space are escaped as `%25`, `%7C`, and `%20`; decoding happens once. Controls, malformed escapes, noncanonical encoding, and malformed `src:`, `asm:`, legacy `h:`, or internal `i:` identifiers return `INVALID_SYMBOL_REFERENCE`; they never fall through to name or location discovery. Non-empty `H:/...`, `H:\...`, `I:/...`, and `I:\...` inputs keep the existing physical-path route, subject to host path validation. Existing names, raw documentation IDs, and source locations remain discovery inputs.

The selected owner and all declaration matches must be unique. A malformed reference returns `INVALID_SYMBOL_REFERENCE`; a missing or renamed declaration returns `SYMBOL_NOT_FOUND`; a wrong origin or source owner returns `TARGET_MISMATCH`; an ambiguous owner or declaration returns `AMBIGUOUS_SYMBOL`; an unrepresentable owner coordinate returns `UNSUPPORTED_IDENTIFIER`; and an unavailable required source compilation returns `WORKSPACE_DIAGNOSTIC`. Each response's recovery action directs callers to rediscover on the intended current target or use available raw-location navigation. These errors do not imply that an unchanged reference became stale because of content edits.

Some declarations cannot be represented by a unique canonical reference, including local functions, anonymous or synthesized declarations, file-local declarations whose IDs do not round-trip uniquely, and declarations without a stable owner coordinate. Their raw name, location, body, and owner metadata remain available where supported. The existing stable-reference availability flags are false, follow-up-tool lists are empty, and nullable reference fields retain their current null/omission behavior. Renderers omit the reference fragment; no location-based or allocated-ID fallback is emitted. Body availability remains independent: a declaration with readable text can still report an available body even when no stable reference can be represented. Existing physical-path selectors keep their prior solution/decompiler-relative base. A source reference supplied to `get_file_skeleton.filePaths` resolves to every declaring regular or generated document, including partial declarations; that tool has no scope/generated-source filter. `find_symbol` considers declarations from materialized Roslyn source-generated documents as well as regular source documents. `get_class_structure` excludes generated declarations when `includeGenerated` is false, while `get_context` rejects a generated target with `INVALID_ARGUMENT`; both can inspect generated source when the filter is true.

Source raw discovery accepts Roslyn documentation IDs, supported declaration names/signatures, and existing source-location selectors. Assembly raw discovery is limited to the selected decompiled owner except where a tool explicitly searches resolved referenced owners. These inputs retain their existing ambiguity rules and are not additional stable IDs. The common Core resolver owns reference parsing; handlers and renderers pass reference strings through unchanged.
