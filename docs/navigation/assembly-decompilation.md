# Assembly Decompilation Core

`AssemblyFingerprintCalculator` canonicalizes an assembly path and fingerprints its length, UTC modification time, and SHA-256 content. The decompilation cache key also includes the decompiler version, effective options, and cache schema version.

`AssemblyDecompilationAdapter` uses ICSharpCode.Decompiler to materialize a managed assembly into a temporary staging directory. It parses generated C# documents for syntax errors and reports incomplete output with diagnostics. It does not write to the analyzed assembly; the FastTests compare the input bytes and timestamp before and after decompilation. Native PE files and invalid managed images return diagnostics instead of escaping as exceptions.

The root PE and dependency streams use `PEStreamOptions.PrefetchEntireImage`. This snapshots the bytes and closes the file streams during construction, allowing an active navigation host to observe a referenced DLL being replaced or removed. A refreshed search reports unresolved references as incomplete rather than returning old dependent symbols. Declaration references remain independent of PE contents; retained analyses still validate their captured owner and resolved-reference snapshot before returning evidence. See [Assembly Navigation](assembly-navigation.md) for how assembly references select an owner.

`AssemblyDecompilationCache` publishes complete or partial, analysable generations behind a current-generation pointer. It validates the manifest against the requested content fingerprint, cache key, resolved references, and a SHA-256 digest for every generated C# document before returning a generation. Captured reference hashes continue to identify immutable analysis requests; cache reads and pointer publication also fingerprint the current bytes at each resolved reference path, so a same-identity replacement cannot make an old request publish successfully. The cache schema version is part of the key, so a schema change invalidates older generations. Concurrent identical publications resolve to an existing published generation. Active decompilation staging directories hold owner locks, so retention skips work in progress while removing inactive staging directories. Incomplete decompilations are not eligible for publication.

`AssemblyRoslynWorkspaceFactory` creates an in-memory `AdhocWorkspace` project from the decompiled documents. It excludes the analyzed assembly from metadata references, adds the core library when needed, and maps each generated document to its assembly origin. Empty document sets and canceled requests fail before a snapshot is returned. The snapshot owns the workspace lifetime and disposes it when the snapshot is disposed. When decompilation reaches its configured timeout, the adapter returns an incomplete result without scanning partially written output, keeping timeout recovery bounded.

The verified component contracts are covered by [assembly decompilation FastTests](../../tests/AiNetCodeNavigator.FastTests/Assemblies/AssemblyDecompilationBoundaryTests.cs) and [cache roundtrip FastTests](../../tests/AiNetCodeNavigator.FastTests/Assemblies/AssemblyDecompilationCacheTests.cs).

`AssemblyReferenceResolver` tries identity-matching adjacent files first, then runtime trusted-platform paths, then the installed .NET Framework GAC. GAC lookup covers `%WINDIR%\Microsoft.NET\assembly` and `%WINDIR%\assembly`, including `GAC_MSIL`, `GAC_32`, `GAC_64` and legacy `GAC` buckets. Each GAC file is checked against the referenced name, exact version, culture and public-key token from PE metadata. A compatible MSIL file takes precedence over a matching architecture-specific file; multiple remaining files produce an explicit ambiguity. Installed higher versions never substitute for GAC references. No analyzed assembly is executed. Tests inject temporary GAC roots and runtime paths instead of relying on the host installation.

The whole-project decompiler first binds to these proven reference paths, including files in GAC version directories, before using ILSpy's search-directory fallback for navigation. Export resolutions disable that assembly fallback so unresolved references cannot be replaced by an invented binding.

`AssemblyExportReferenceResolver.Resolve` exposes an independent offline reference preflight. Its returned edges retain the referring assembly path, requested identity, resolved path, SHA-256 and `adjacent`, `runtime` or `gac` provenance. An optional reference predicate selects which resolved edges are traversed; excluded edges remain recorded and available to the decompiler. Export traversal defaults to a maximum depth of 128 and 4096 nodes, independently of navigation's depth-eight/128-node boundaries. Cycles and repeated paths remain proven edges without repeated traversal. `IsComplete` becomes false for traversal boundaries, ambiguity, unreadable candidates or invalid metadata; a missing dependency is a recorded limitation in a completed search. Consumers must inspect both completeness and unresolved edges before publication.
