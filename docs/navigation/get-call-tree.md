# Call Tree Core Engine

The Core call tree engine builds a bounded graph around a Roslyn symbol. Incoming traversal groups source references by caller and retains self-recursive edges. Outgoing traversal resolves invocations, explicit and target-typed object creation, and non-invoked member access from block-bodied and expression-bodied declarations. Call sites retain one-based line and column, so repeated calls on one line remain separate. A type seed returns the type and up to five method hints without expanding a graph.

Call sites expose `call`, `memberAccess`, or `staticVirtualOrInterfaceTarget` evidence. Ambiguous bindings appear under unresolved call sites as `possibleTarget` with candidate names; locations without a bound symbol are marked `unresolved`. Only bound invocations and constructors use `call` or `staticVirtualOrInterfaceTarget`; virtual/interface method groups and property uses remain `memberAccess`. Candidate names stay attached to possible-target sites. These labels report static source evidence and make no claim about runtime dispatch. Assembly call trees decompile the selected owner and carry the same call-site evidence through owner merging.

`RequestedDepth` is clamped to 1–5. `TopN` is clamped to at least one edge per expanded symbol; in `Both` mode the incoming groups are considered first, then outgoing groups use the remaining budget. The builder stops at 250 distinct nodes. `Truncated` is true when known edges were omitted or queued nodes remain unexpanded. `HiddenEdgeCount` counts only discovered groups omitted by `TopN` or the hard node cap; `PendingNodeCount` counts queued nodes whose outgoing or incoming relationships were not scanned. Reaching exactly 250 fully expanded terminal nodes does not by itself mark the graph truncated. Symbols are deduplicated with Roslyn symbol equality, call sites for the same edge are combined, and node IDs are local `n1`, `n2`, ... labels.

Outgoing source targets are always retained, including targets in `System` or other framework-named namespaces. Metadata targets are retained by default unless they resolve to BCL assemblies or namespaces. Set `IncludeBcl` to include those framework targets too.

Source-backed nodes carry stable references when the exact declaration round-trip succeeds. Assembly reference lines also print the canonical `targetPath` of the node owner. Both renderers distinguish node count, relationship edge count, edge-site count, and candidate/unresolved site count. Sites count source locations, not distinct graph nodes or proven runtime invocations. Candidate/unresolved totals include incoming edge sites and outgoing unresolved sites; identical caller/location/evidence entries across those collections count once, while different callers or columns remain distinct. ASCII output lists graph edges, references, known omitted edges, and pending expansions; Mermaid output uses the same nodes and edges, places references and owner paths in comments, and annotates pending expansions. Mermaid labels replace quotes and line breaks so symbol names and paths do not break the flowchart syntax. See [Shared Symbol Resolution](symbol-resolution.md) for reference behavior.

The Core entry point throws `ArgumentNullException` for a missing request, solution, or seed symbol. Both renderers throw `ArgumentNullException` for a missing payload. Cancellation is honored during traversal. The public `get_call_tree` handler defaults to incoming traversal, depth 2, `topN` 10, ASCII output, excludes BCL metadata targets, and sets `includeDiagnostics=false`. Assembly calls can opt in to decompilation/navigation and graph-expansion diagnostics; graph, diagnostics, and reported `snapshotId` come from the same leased owner generation, and the diagnostic count remains visible when samples are omitted. Source calls do not add diagnostic sections. It accepts `scopeType` (`all`, `production`, or `tests`) and `includeGenerated` (false by default); these filters apply to source nodes before graph limits and source references retain the original solution identity. Assembly targets resolve references only in their supplied owner and format graph nodes when their declarations belong to a proven owner source. With `includeReferences=true`, the handler checks each opened owner against the root-captured PE hash and transitive reference snapshot before graph expansion, then merges owner-scoped graphs, applies `topN` fanout globally after merging, and caps visible nodes and edges at 250. Changed owners fail with `STALE_SNAPSHOT`; known root closure boundaries remain explicit incomplete analysis. Duplicate edges merge only when source node, destination node, and dispatch kind match. References are created only for final visible nodes. Graph nodes found through metadata are mapped by full original PE identity to a unique source owner; unproven metadata nodes receive no reference. Assembly relationship analysis continues to retain generation leases and reference provenance. See [MCP Navigation Registration Status](mcp-registration-status.md) for current handler-test scope.
