# Namespace Tree Core Scanner

`NamespaceTreeScanner.ScanSolutionAsync` builds a hierarchical view of declared source namespaces for C# projects in a solution or one named project. Non-C# projects are skipped in a solution scan; naming a non-C# project returns a recoverable error. `ProjectName` matching is case-insensitive and trims surrounding whitespace, matching index scope behavior. The payload and formatted title use the selected project's actual name.

The scanner reads Roslyn project documents and does not change source files. By default it excludes generated documents using the same classifier as symbol navigation, where `IncludeGenerated` also defaults to false. Set `NamespaceTreeScanOptions.IncludeGenerated` to `true` to include generated source trees, matching the symbol navigation opt-in. The payload exposes this option, and formatted output labels whether generated source was included or excluded. Therefore, generated-only namespaces are omitted by default and included when the option is enabled. File-scoped and block-scoped declarations share the same namespace tree. Roslyn combines partial type declarations in a project, so each partial type contributes one type to its namespace. Matching namespace names from different projects share a tree node, while their source type counts are added.

Namespace nodes are ordered by ordinal name. Parent namespace segments remain in the result when they contain descendant types, even when they declare no direct types. The total namespace count includes these parent nodes. A namespace with no selected source types anywhere below it is omitted. Types declared directly in the global namespace are not represented as namespace nodes.

`NamespaceTreeScanOptions` bounds each scan. The default maximum depth is 32 levels; `MaxResults` defaults to 50 and has a hard cap of 200 returned namespace nodes. Values below one are clamped to one, and values above the hard caps are clamped to the caps. Clamping is exposed through requested/effective bound fields and `BoundsWereClamped`. Result limiting uses one budget across the entire hierarchy, including its parent nodes. The structured tree and formatted text use the same bounded projection. `TotalNamespaces` counts nodes found within the effective depth; `ShownNamespaces` counts returned nodes. `TotalTypes` counts all named-namespace source types in the selected target and generated-source mode, including types below the effective depth and in namespace nodes omitted by the result limit. Each `NamespaceNode.TypeCount` counts only the types declared directly in that namespace. An ancestor can therefore have a direct `TypeCount` of zero while `TotalTypes` includes types in its omitted descendant namespaces. `TruncatedBy` reports `maxDepth` or `maxResults` when the scan omitted namespace nodes.

The scanner does not provide offset or cursor pagination. A truncated result includes an English `NextAction` that recommends raising `MaxResults` up to the hard cap or selecting one project. Formatted labels, truncation guidance, and scanner-authored error messages are also in English. An unknown project name, a project that cannot produce a compilation, or another scan failure returns an empty payload with an explanatory `Error`. Cancellation is propagated to the caller.

The MCP host currently registers `get_namespace_tree` for source and managed-assembly targets and adds public namespace-prefix, kind, and include-types filters. The initial public integration test exercises the source path; complete source/assembly behavior and public budget/error parity remain open. See [MCP Host](../mcp-host.md).
