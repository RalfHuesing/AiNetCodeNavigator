# Namespace Tree Core Scanner

`NamespaceTreeScanner.ScanSolutionAsync` builds a hierarchical view of declared source namespaces for a solution or a named project. It reads Roslyn project documents and does not change source files. File-scoped and block-scoped declarations share the same namespace tree. Roslyn combines partial type declarations in a project, so each partial type contributes one type to its namespace. Matching namespace names from different projects share a tree node, while their source type counts are added.

Namespace nodes are ordered by ordinal name. Parent namespace segments remain in the result when they contain descendant types, even when they declare no direct types. The total namespace count includes these parent nodes. A namespace with no source types anywhere below it is omitted. Types declared directly in the global namespace are not represented as namespace nodes.

`NamespaceTreeScanOptions` bounds each scan. The default maximum depth is 32 levels; `MaxResults` defaults to 50 and has a hard cap of 200 returned namespace nodes. Values below one are clamped to one, and values above the hard caps are clamped to the caps. Clamping is exposed through requested/effective bound fields and `BoundsWereClamped`. Result limiting uses one budget across the entire hierarchy, including its parent nodes. The structured tree and formatted text use the same bounded projection. `TotalNamespaces` counts nodes found within the effective depth; `ShownNamespaces` counts returned nodes. `TruncatedBy` reports `maxDepth` or `maxResults` when the scan omitted namespace nodes.

The scanner does not provide offset or cursor pagination. A truncated result includes a `NextAction` that recommends raising `MaxResults` up to the hard cap or selecting one project. An unknown project name, a project that cannot produce a compilation, or another scan failure returns an empty payload with an explanatory `Error`. Cancellation is propagated to the caller.
