# Namespace Tree Core Scanner

`NamespaceTreeScanner.ScanSolutionAsync` builds a hierarchical view of declared source namespaces for C# projects in a solution or one named project. Non-C# projects are skipped in a solution scan; naming a non-C# project returns a recoverable error. Project selection accepts an exact name, an unambiguous partial name, or a project path. A duplicate name or a namespace prefix present with source types in multiple projects returns `AMBIGUOUS_SYMBOL` and lists project paths so the caller can select one owner. The payload and formatted title use the selected project's actual name.

The scanner reads Roslyn project documents and does not change source files. By default it excludes generated documents using the same classifier as symbol navigation, where `IncludeGenerated` also defaults to false. Set `NamespaceTreeScanOptions.IncludeGenerated` to `true` to include generated source trees, matching the symbol navigation opt-in. The payload exposes this option, and formatted output labels whether generated source was included or excluded. Therefore, generated-only namespaces are omitted by default and included when the option is enabled. File-scoped and block-scoped declarations share the same namespace tree. Roslyn combines partial type declarations in a project, so each partial type contributes one type to its namespace. Matching namespace names from different projects share a tree node, while their source type counts are added.

Namespace nodes are ordered by ordinal name. Parent namespace segments remain in the result when they contain descendant types, even when they declare no direct types. The total namespace count includes these parent nodes. A namespace with no selected source types anywhere below it is omitted. Types declared directly in the global namespace are not represented as namespace nodes.

`NamespaceTreeScanOptions` bounds each scan. The default maximum depth is 32 levels; `MaxResults` defaults to 50 and has a hard cap of 200 namespace nodes and, independently, 200 displayed type entries. Values below one are clamped to one, and values above the hard caps are clamped to the caps. Clamping is exposed through requested/effective bound fields and `BoundsWereClamped`. Namespace-node limiting uses one budget across the entire hierarchy, including parent nodes. When `IncludeTypes` is true, each shown type entry includes its name, kind, source path, line, and a handoff only when the target identity can prove one; type entries have their own deterministic scan-wide `MaxResults` bound. The structured tree and formatted text use the same bounded projection. `TotalNamespaces` counts nodes found within the effective depth; `ShownNamespaces` counts returned nodes. `TotalTypes` counts all named-namespace source types in the selected target and generated-source mode, including types below the effective depth and entries omitted by either result bound. Each `NamespaceNode.TypeCount` counts the types declared directly in that namespace even when `IncludeTypes` is false. An ancestor can therefore have a direct `TypeCount` of zero while `TotalTypes` includes types in its omitted descendant namespaces. `TruncatedBy` reports `maxDepth` or `maxResults` when the scan omits namespace nodes or type entries.

The scanner does not provide offset or cursor pagination. A truncated result includes an English `NextAction` that recommends raising `MaxResults` up to the hard cap or selecting one project. Formatted labels, truncation guidance, and scanner-authored error messages are also in English. An unknown project name, a project that cannot produce a compilation, or another scan failure returns an empty payload with an explanatory `Error`. Cancellation is propagated to the caller.

For source MCP calls with no `project` or `namespacePrefix`, the scanner returns a depth-one project overview with per-project namespace/type counts. Duplicate project names include their relative project paths. Supplying a namespace prefix without a project selects the unique C# project that declares source types under that namespace; zero matches is invalid and multiple matching projects are ambiguous. A project or unique namespace selection drills into the namespace tree.

The MCP host registers `get_namespace_tree` for source and managed-assembly targets and adds public namespace-prefix, kind, and include-types filters. A no-filter source query returns a depth-one project overview with namespace/type counts and relative paths for duplicate project names. A prefix without a project searches descendant namespaces and selects only a unique project owner; zero matches are invalid and multiple project owners return `AMBIGUOUS_SYMBOL`. Source and assembly type entries carry target-bound handoffs, and stdio tests roundtrip both through `get_symbol_body`. `SourceToolsContractTests` directly checks a source namespace result, a kind error, generated-source filtering, and a compact projection under separate 512-byte and 512-token caps. Scanner tests cover exact project-path disambiguation when Roslyn projects share a name, full totals before presentation limits, and namespace depth. See [MCP Host](../mcp-host.md).
