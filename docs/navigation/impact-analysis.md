# Symbol Impact Core Engine

`ImpactAnalyzer.AnalyzeSymbolImpactAsync` accepts an already-resolved Roslyn symbol and searches its references across every source project in the solution, including test projects. Each reference location is assigned to its enclosing method or property and expanded breadth-first to find callers of those callers. The Core API has no project or production/test filter; its scope is the whole solution.

Call-site entries carry a solution-relative file path, one-based line and column, calling member, project name, traversal depth, and a project-bound `h:` handoff when a source identity is available. `ReachedFromSymbolId` and `ReachedFromSymbolHandoffId` identify the symbol whose reference search found each call site. Call sites are de-duplicated and sorted by depth, project, path, line, caller identity, reached-from identity, and column. Distinct calls on one line and converging paths on the same call location remain separate. `FindReferencesResolver` uses the same location and ordering keys. Both caller and reached-from handoffs resolve to their source symbols; line and column identify the reference location.

`DirectCallersCount` counts distinct depth-one call sites. `TransitiveCallSitesCount` counts distinct call sites beyond the first level. `TransitiveImpactCount` preserves the original total-impact meaning and includes both direct and transitive sites. Affected project and file summaries cover all discovered sites before the display limit, so the summary can include projects omitted from `CallSites`.

Depth defaults to three and is clamped to 1–3. The expanded-symbol budget defaults to 200; a lower `maxNodes` narrows it and a higher value is clamped to 200. `maxResults` defaults to 50 and is normalized to at least one. Symbol equality prevents repeated expansion in cycles. `RequestedDepth`, `EffectiveDepth`, `VisitedSymbolCount`, `EffectiveNodeLimit`, `IsTruncatedByNodeLimit`, and `IsDepthClamped` describe traversal bounds. `IsTruncated` reports display-limit truncation, and `IsComplete` is false when results were hidden, queued symbols remained at the node cap, or the requested depth was clamped.

Null symbols and solutions throw `ArgumentNullException`; `maxNodes` below one throws `ArgumentOutOfRangeException`. Cancellation is checked during traversal and reference collection. Identifier lookup, ambiguity, and stale or invalid handoff errors belong to the shared symbol-resolution layer, which runs before this Core API.

For managed-assembly targets, the public `get_impact` handler resolves an owner-bound assembly handoff and emits caller handoffs only for declarations proven to belong to an assembly's decompiled source. With `includeReferences=true`, it scans the bounded resolved owner closure to the requested depth (capped at three) and includes each caller's canonical `ownerTargetPath`; Root → B → C stdio follows B.Run and C.LocalRun handles to their respective bodies. The fixture verifies depth-2 traversal to A.Run and a complete depth-3 query. Global result limits cap visible call sites without reducing known direct/transitive totals. Closure, depth, output, and unresolved-owner bounds still report incompleteness when they prevent the requested traversal.

For source targets, `detailLevel="callers"` and `detailLevel="change-context"` use the Git worktree as the change source. The handler resolves `gitRef` as a commit before passing it to Git, includes staged and unstaged tracked changes plus untracked files when `gitRef` is omitted, and reports clean and non-Git states explicitly. It parses zero-context per-file hunks and associates each changed current line with the innermost declaration; same-line sibling declarations remain separate, while callers mode selects only externally visible methods and constructors. `maxChangedSymbols` limits displayed change-context entries after scanning, and `totalChangedSymbols` preserves the discovered count. `changedFiles` and unresolved paths likewise have total counts before display limits. Deleted-only hunks and files without a current safe declaration mapping keep completeness partial instead of inventing a neighboring symbol. These source Git paths are exercised through stdio in a `.git`-file worktree, including staged, unstaged, untracked, mixed addition/deletion, clean, non-Git, and invalid-ref cases. Child-process cancellation and unusual-path/partial-mapping cases remain under verification.
