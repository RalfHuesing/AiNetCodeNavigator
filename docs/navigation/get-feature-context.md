# Get Feature Context

`FeatureContextScanner.ScanAsync` resolves one source symbol and combines its declaration/signature, incoming callers, and statically matched test recommendations. It uses the [shared symbol resolution contract](symbol-resolution.md), including reusable `h:` handoffs and structured ambiguity candidates. The declaration and source callers carry opaque `h:` handoffs when a stable source identity is available; test-method handoffs point to the attributed method. These IDs can be passed back to the scanner to resolve those symbols.

Scope is applied to caller locations. Test candidates are collected independently of that caller scope, so `scopeType=production` can still return tests for a production target. Caller classification uses the Roslyn project and document path, so a neutral file name such as `Shared.cs` in a test project remains in test scope. The request defaults to 20 callers and 20 test candidates. Each requested maximum is clamped to 1 through 50, results are sorted deterministically before truncation, and the payload reports totals plus truncation flags.

Unresolved identifiers return a payload with a structured navigation error; ambiguous identifiers include selectable resolution candidates. Invalid or unresolvable handoffs return the same error form. Null requests/solutions and blank identifiers throw argument exceptions. Markdown rendering rejects a null payload with `ArgumentNullException`.

Test entries reuse the [test candidate contract](test-context.md), including source-located evidence and explicit implementation/reference/candidate expansion limits. The structured `FeatureContextPayload.EvidenceMode` is always `static-test-candidates-only`; the Markdown labels the same boundary and states that execution and coverage are not verified. These entries do not establish test execution or coverage. The feature-context result contains navigation data only and does not include lint findings or quality metrics. The public handler defaults to 10 callers and 10 tests (Core defaults remain 20), accepts scope and generated-source controls, and supports shared response byte/token limits and outer continuation routing. `SourceToolsContractTests` invokes the handler directly, checks its source result and empty-identifier error, measures the rendered text independently under a 512-byte cap and a 512-token cap, and verifies caller scoping plus tests independent of caller scope.
