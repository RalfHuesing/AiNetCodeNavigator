# MCP Navigation Registration Status

The production catalog exposes nineteen read-only navigation tools. The current handler contract evidence uses the original SDK definitions, direct validators and transport-free tool handlers. It covers source and assembly routes, exact budgets, handoff consumers, and domain limits. Retained child-stdio, MCP client/stream, handshake, and full JSON-RPC tests remain in the test projects under `E2EIntegration`; they are excluded from current completion gates. Their prior findings are historical implementation evidence, not current transport-free acceptance evidence. See the [tool reference](../tools/README.md).

## Current transport-free handler coverage

`SourceToolsContractTests.SourceHandlersReturnNavigableResultsAndTypedDomainErrorsWithoutTransport` invokes all eight source structure/symbol handlers and checks actual results, owner followups, domain errors, and separate byte/token projections. `SourceRelationshipToolsContractTests.SourceRelationshipHandlersReturnNavigableResultsErrorsAndBoundedProjections` covers source relationship routes and recovery. `RelationshipToolsContractTests.GetImpact_OriginalSdkContractRequiresSymbolAndRoutesSourceAndAssemblySymbols` covers the required impact identifier, source/assembly routing, caller handoffs, and retries. `AssemblyToolsContractTests.AssemblyNavigationHandlersReturnOwnerResultsAcrossAllSixteenRoutes` invokes all 16 assembly-capable handler routes; focused assembly cases cover replacement generations, target locks, nested response/domain pages, defaults, and owner followups.

M2-T1 source and shared list handlers now page complete discovered symbol, reference, implementation, hierarchy, impact, class-member, namespace/type, and loaded-index inventories through the existing long-running/continuation store. Positive page sizes do not set analysis completeness to partial; source filters run before totals and paging, while traversal, depth, and owner-closure limits remain explicit. `StructureInventoriesReachEntriesBeyondThePreviousTwoHundredEntryCaps` verifies 205 class members and 207 combined namespace/type rows through both Source and Assembly routes, reconstructing each outer response before following the domain cursor and changing page size between pages. `GetIndexScope_SdkDefinitionPublishesSharedRoutingParameters` checks actual SDK-loaded `net10.0` context, stable canonical project identity after a separate runtime reload, and full inventory paging. Red runs with the prior caps restored fail on Source and Assembly class structure (one page instead of two), Source and Assembly namespace inventory (201 instead of 207 entries), direct references (one page instead of four), and implementations (one page instead of three). Call-tree, dependency-graph traversal, and body windows remain bounded workflows rather than result lists.

The source and assembly lifecycle cases exercise `find_symbol` → runtime disposal → a fresh runtime → `get_symbol_body` on the actual owner path. Disposed handles return `HANDOFF_UNKNOWN`; repeated disposal of the old runtime leaves a newly issued fresh-runtime handle usable. They do not start a host process or exercise a protocol handshake.

## Exercised handler paths

The source fixture exercises `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, symbol-based `get_impact`, file- and symbol-mode `dependency_graph`, source-handoff and SDK reference-pack `resolve_type_origin`, `get_feature_context`, and `get_test_context`. Core tests verify exact source project ownership for same-named declarations, plus production/test/generated filter-before-limit behavior and original-identity handoff roundtrips. The transport-free `SourceRelationshipToolsContractTests` also calls the actual source relationship handlers for normal results, source errors and individually byte-/token-limited projections; visible relationship handoffs are followed through the body consumer, and paged bodies are reconstructed against broad identical queries. The public dependency graph regression uses duplicate full type names, identical assembly names, and identical Roslyn project names at different project paths; it confirms symbol handoffs and exact or ambiguous file paths retain owner identity, and that source results print `Project.Name` instead of assembly identity. The same fixture exercises the source namespace project overview, ambiguous project/prefix choices, exact project-path drilldown, and a namespace type handoff through `get_symbol_body`.

The managed fixture exercises `get_assembly_context` with body, class structure, actual type-reference callers, impact, and a caller-handoff-to-body roundtrip; it checks detail-level validation, body truncation, a 512-byte explicit override, and blank symbol rejection. It also exercises `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, assembly `resolve_type_origin`, assembly symbol `get_impact`, and `get_file_skeleton` with `get_symbol_body` followups. Assembly `get_type_hierarchy` returns an actual `PagedBeta` subtype handle from the `PagedAlpha` hierarchy; `find_implementations` returns `PagedBeta` for `IBetaContract`. Both emitted handles are followed to the owning assembly body, and using either handle with a different managed target returns `TARGET_MISMATCH`. The owner-closure tests for find_references, call_tree, impact, and context cover Root → B → C traversal through depth 2; references and impact also verify a complete depth-3 query on this fixture. An `inspect_assembly` type handoff → skeleton → member handoff → body path is tested. Source skeleton requests accept absolute files and a `../Shared` indexed compile include. A shared physical file included by two projects is ambiguous by path; a project-specific h selects the owner declaration file and its member h can be followed to the body. A namespace type handoff from the assembly target resolves to its body and class structure using the owning DLL path; passing a different managed DLL to `get_class_structure` returns `INVALID_ARGUMENT`. Search tests verify literal-by-default matching, explicitly selected regex, declaration-kind and C# file filtering, and matched-file `maxFiles` behavior: a nonmatching source file sorts before matching files, the capped scan returns real hits in one matched path, reports `truncatedBy=maxFiles`, and an uncapped query finds hits in multiple paths. Search domain pages are verified through the selected matched-file scope, including a nonmatching first file, multiple result lines in the selected file, hidden later matched files, and a final response that stays truncated by `maxFiles` without issuing another cursor. The public search cursor is bound to query, filters, target, root content, and resolved references; tests cover replay, wrong query/target, root replacement, and a separate Core regression for transitive reference replacement. Search results for types and methods include owner-bound handoffs; public type and method calls were followed through `get_symbol_body`, types through `get_class_structure`, and a foreign target was rejected. Qualified type lookup and public `maxFiles=0`/`maxResults=0` behavior are covered. The public assembly extension query includes resolved reference owners, pages every returned extension, follows each owner handoff to its owning body, and rejects a changed page size. A separate public stdio fixture emits A→B→C managed assemblies and checks the emitted PE references: A references B and B references C. Searching C through A reports C's canonical owner `targetPath`; that same handoff returns C's decompiled body with C as the requested target and produces `TARGET_MISMATCH` when A is supplied. Replacing C at the same path in the active host makes the old handoff return `STALE_SNAPSHOT`; a fresh search and handle return the replacement body. The test then deletes C while the same host is still active: a fresh Root search reports no C match with `unresolvedReferences` and truncated completeness, and using the old C handoff through the live Root target fails without stale text. Public body calls with only unknown identifiers return MCP errors; a mixed valid/unknown batch retains its successful body and reports truncated completeness. The Assembly inspection consumer follows response-window pages and retries a line-safe page with its advertised minimum byte budget when 512 bytes cannot contain the next complete line. A separate real stdio consumer runs `inspect_assembly` at `maxResults=1` through all domain pages, checks each type handoff ID appears once, reaches a complete final status, replays the first domain cursor, and verifies that changing `maxResults` rejects the old cursor.

The shared result preamble now reports a short owner-bound `snapshotId`, escaped one-line `analyzedScope`, analysis completeness, result-page availability, and concrete omissions on source and assembly routes. `operationToken` polls work, `continuationToken` reads immutable outer text pages, and opaque `resultCursor` values advance completed source and assembly domain lists. Transport-free tests cover nested outer/domain pages, query/target/snapshot/section binding, replay, expiry, capacity, cancellation, and exact byte/token retry minima, including compact `RESPONSE_BUDGET_TOO_SMALL` responses at 80 and 120 tokens. A source edit creates a new snapshot ID while a previously issued outer page remains readable with its original ID.

The assembly type-relationship regression also follows an interface-method implementation, interface-property implementation, virtual method override, and virtual property override from their emitted owner handles to `get_symbol_body`. These cases use `get_class_structure` to select property handles because assembly `search_assembly` only advertises declaration handoffs for type and method declaration matches.

The public assembly symbol-input regression now exercises raw type/method documentation IDs, a qualified method name, line-only and line/column positions, direct class structure, hierarchy, implementations, dependency graph, and type origin. It follows a raw body result's owner-bound handoff into class structure. With `includeReferences=true`, a raw C.Read query rooted at A resolves through current B/C owner leases for references, call tree, impact, and context. The ambiguous raw name `Run` returns A- and B-owned choices, and the B choice is followed to B's body. A known referenced-file position outside its source bounds returns `INVALID_ARGUMENT`. Opaque handoffs remain strict: an actual source handle from the same host sent to the assembly body route returns `TARGET_MISMATCH`; unknown assembly handles return `HANDOFF_UNKNOWN`.

One-token stdio calls verify sanitized MCP `InvalidParams` for schema-valid unsupported `scopeType` and `direction` and a missing target. Scope failures are also checked at 16 and 32 tokens, covering both budget-specific exceptions and early error results that bypass the usual formatter. Assembly search validation rejects missing patterns and invalid explicitly selected regexes; transport-free integration tests verify inspect/search/extension compact defaults and detailed-diagnostics opt-in. The affected stdio fixture consumer has been updated for direct `handoffId` fields and the removed assembly arguments; the E2E suite was excluded from the M2-T2 focused verification and remains unverified in that gate.

The retained real-host input matrix sends one tool-specific invalid call to each of the nineteen navigation registrations and checks its typed `INVALID_ARGUMENT` or `HANDOFF_UNKNOWN` result. Separate host checks cover required-field, wrong-type, out-of-range, unknown-key, semantic-enum, and unfittable error-envelope cases, followed by successful calls to verify host survival. `get_feature_context` and `get_test_context` reject blank identifiers before dispatch; the prior empty feature identifier became a generic `OPERATION_FAILED`.

The historical `tools/list` test checked purpose descriptions and critical allowed values for the former catalog. Current registered tool names and schemas are maintained in the [tool reference](../tools/README.md). Public stdio compares omitted and zero limits for `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, and `get_assembly_context`; it also verifies `get_call_tree.includeDiagnostics` false/true. A large assembly fixture reconstructs 200 `find_symbol` results, an 800-line body, and the same body inside `get_assembly_context` across response-window pages while preserving complete, line-safe content.

For assembly `get_impact` with `includeReferences` omitted or false, raw method documentation IDs, a qualified name, and a host-emitted valid position now resolve through an exact target-bound assembly handoff; they match the `h:` route's caller totals, and the emitted caller handoff reaches its body. Each raw form is exercised with both omitted and explicit false. The original opaque `h:` route stays owner-bound and strict.

A transport-free `get_impact` contract test checks the original SDK schema and direct handler routes for source and assembly targets, including rejection of removed Git fields. ## Current verification boundaries

The detailed stdio scenarios above are retained test descriptions from earlier public-contract testing; they are not current gate results.

Current completion gates exclude child-process stdio, MCP client/server streams, handshake, JSON-RPC, and full report-publishing E2E cases. The single explicitly selected AiNetReview report-publication test is a separate user-requested report check and is not MCP acceptance evidence. The loader's tested MSBuild write guards cover concrete configured imports and output-path redirection; AiNetCodeNavigator is not a security sandbox for arbitrary executable MSBuild targets.
