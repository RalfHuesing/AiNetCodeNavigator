# MCP Navigation Registration Status

The production catalog exposes all twenty navigation tool names and two maintenance tools. The current real-stdio integration test exercises the thirteen handlers added for Cluster 9.2 on a deterministic source solution and a small managed assembly. That is implementation evidence for the listed paths, not acceptance of the full public reference contract.

## Exercised handler paths

The source fixture exercises `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, symbol-mode `get_impact`, Git `change-context`, file- and symbol-mode `dependency_graph`, source-handoff and SDK reference-pack `resolve_type_origin`, `get_feature_context`, and `get_test_context`. Core tests verify exact source project ownership for same-named declarations, plus production/test/generated filter-before-limit behavior and original-identity handoff roundtrips. The public dependency graph regression uses duplicate full type names, identical assembly names, and identical Roslyn project names at different project paths; it confirms symbol handoffs and exact or ambiguous file paths retain owner identity, and that source results print `Project.Name` instead of assembly identity. The same fixture exercises the source namespace project overview, ambiguous project/prefix choices, exact project-path drilldown, and a namespace type handoff through `get_symbol_body`.

The managed fixture exercises `get_assembly_context` with body, class structure, actual type-reference callers, impact, and a caller-handoff-to-body roundtrip; it checks detail-level validation, body truncation, a 512-byte explicit override, and blank symbol rejection. It also exercises `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, assembly `resolve_type_origin`, assembly symbol `get_impact`, assembly `get_file_tree` and `get_file_skeleton`, and `get_symbol_body` followups. Assembly `get_type_hierarchy` returns an actual `PagedBeta` subtype handle from the `PagedAlpha` hierarchy; `find_implementations` returns `PagedBeta` for `IBetaContract`. Both emitted handles are followed to the owning assembly body, and using either handle with a different managed target returns `TARGET_MISMATCH`. The owner-closure tests for find_references, call_tree, impact, and context cover Root → B → C traversal through depth 2; references and impact also verify a complete depth-3 query on this fixture. The tree → skeleton → member handoff → body path is tested, and a neighboring DLL-folder sentinel is excluded. Source skeleton requests accept absolute files and a `../Shared` indexed compile include. A shared physical file included by two projects is ambiguous by path; a project-specific h selects the owner declaration file and its member h can be followed to the body. A namespace type handoff from the assembly target resolves to its body and class structure using the owning DLL path; passing a different managed DLL to `get_class_structure` returns `INVALID_ARGUMENT`. Public search cases verify automatic regex promotion, declaration-kind and C# file filtering, and matched-file `maxFiles` behavior: a nonmatching source file sorts before matching files, the capped scan returns real hits in one matched path, reports `truncatedBy=maxFiles`, and an uncapped query finds hits in multiple paths. Search domain pages are verified through the selected matched-file scope, including a nonmatching first file, multiple result lines in the selected file, hidden later matched files, and a final response that stays truncated by `maxFiles` without issuing another cursor. The public search cursor is bound to query, filters, target, root content, and resolved references; tests cover replay, wrong query/target, root replacement, and a separate Core regression for transitive reference replacement. Search results for types and methods include owner-bound handoffs; public type and method calls were followed through `get_symbol_body`, types through `get_class_structure`, and a foreign target was rejected. Qualified type lookup and public `maxFiles=0`/`maxResults=0` behavior are covered. A separate public stdio fixture emits A→B→C managed assemblies and checks the emitted PE references: A references B and B references C. Searching C through A reports C's canonical owner `targetPath`; that same handoff returns C's decompiled body with C as the requested target and produces `TARGET_MISMATCH` when A is supplied. Replacing C at the same path in the active host makes the old handoff return `STALE_SNAPSHOT`; a fresh search and handle return the replacement body. The test then deletes C while the same host is still active: a fresh Root search reports no C match with `unresolvedReferences` and truncated completeness, and using the old C handoff through the live Root target fails without stale text. Public body calls with only unknown identifiers return MCP errors; a mixed valid/unknown batch retains its successful body and reports truncated completeness. The source Git fixture is a linked worktree whose root contains a `.git` file. The Assembly inspection consumer follows response-window pages and retries a line-safe page with its advertised minimum byte budget when 512 bytes cannot contain the next complete line. A separate real stdio consumer runs `inspect_assembly` at `maxResults=1` through all domain pages, checks each type handoff ID appears once, reaches a complete final status, replays the first domain cursor, and verifies that changing `maxResults` rejects the old cursor.

The assembly type-relationship regression also follows an interface-method implementation, interface-property implementation, virtual method override, and virtual property override from their emitted owner handles to `get_symbol_body`. These cases use `get_class_structure` to select property handles because assembly `search_assembly` only advertises declaration handoffs for type and method matches.

The public assembly symbol-input regression now exercises raw type/method documentation IDs, a qualified method name, line-only and line/column positions, direct class structure, hierarchy, implementations, dependency graph, and type origin. It follows a raw body result's owner-bound handoff into class structure. With `includeReferences=true`, a raw C.Read query rooted at A resolves through current B/C owner leases for references, call tree, impact, and context. The ambiguous raw name `Run` returns A- and B-owned choices, and the B choice is followed to B's body. A known referenced-file position outside its source bounds returns `INVALID_ARGUMENT`. Opaque handoffs remain strict: an actual source handle from the same host sent to the assembly body route returns `TARGET_MISMATCH`; unknown assembly handles return `HANDOFF_UNKNOWN`.

One-token stdio calls now verify sanitized MCP `InvalidParams` for schema-valid unsupported `scopeType` and `direction`, a missing target, and an unsupported `inspect_assembly` detail level. Scope and assembly-detail failures are also checked at 16 and 32 tokens, covering both budget-specific exceptions and early error results that bypass the usual formatter.

The `tools/list` contract test checks purpose descriptions and critical allowed values, including all three `get_file_tree.view` modes (`tree`, `files`, `summary`), source `find_symbol.kind` values, namespace type kinds, assembly detail levels, and search modes. Public stdio compares omitted and zero limits for `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, `get_assembly_context`, and Git `get_impact`; it also verifies `get_call_tree.includeDiagnostics` false/true. A large assembly fixture reconstructs 200 `find_symbol` results, an 800-line body, and the same body inside `get_assembly_context` across response-window pages while preserving complete, line-safe content.

## Current unverified contracts

- Core and public stdio tests verify transitive Root → B → C closure behavior. Core tests cover cursor invalidation and refreshed handoffs after missing/replaced C while the root PE stays unchanged; public stdio verifies owner-path routing, body roundtrip, stale handoff failure after replacement, fresh replacement body, and incomplete search/body errors after C is deleted in the live host. Assembly `get_type_hierarchy` and `find_implementations` are tested for root-decompiled source handles, member implementations/overrides, and cross-target rejection. Assembly `find_references(includeReferences=true)` scans referenced source through depth 2: a C-owned method handle finds B's caller and follows the chain to A's caller; the A-owned handle roundtrips to its canonical body. A depth-3 query completes on the fixture. A type relationship also returns a B-owned type handle. Foreign handles fail, replaced-owner handles are stale, and unresolved owners remain incomplete. Assembly `get_call_tree(includeReferences=true)` merges owner-scoped source graphs through depth 2, emits target paths for proven owner handles, maps outgoing metadata callees through their actual PE identity, and globally applies topN fanout after merging, then caps nodes and edges at 250. Duplicate edges retain distinct dispatch kinds. Incoming C.Read → B.Run → A.Run and outgoing A.Run → B.Run → C.Read were followed to their correct bodies; incoming C.Read callers in B/C and outgoing B.Run → C.Read were followed in ASCII and Mermaid, including the Mermaid C-owner handoff roundtrip. Separate stdio cases assert global topN, both hard caps, and honest truncation. Symbol-mode `get_impact(includeReferences=true)` traverses the bounded owner closure through depth 2, preserves known aggregate totals when visible call sites are capped, and follows A/B/C caller handles to owner bodies; depth 3 completes on the fixture. `get_assembly_context(includeReferences=true)` uses the same relationship scanners for Caller and Impact sections; the depth-2 fixture is complete and its B.Run, C.LocalRun, and A.Run handles follow to owner bodies. Source and assembly `dependency_graph` are tested using exact symbol/file identities; edge endpoint handoffs follow to the correct source or assembly body, and foreign/source handles fail with `TARGET_MISMATCH`. Broader relationship closure remains open.
- `inspect_assembly` and `search_assembly` distinguish their bound `v1.<offset>.<binding>` domain cursors from the host's fixed-width decimal response-window page token. Outer byte/token pages still have their own immutable snapshot and must be completed before following the domain cursor carried by the payload. The full replay/error/budget matrix for every tool is not established.
- The complete public parameter matrix remains open. The targeted field comparison and tests now cover all twenty tool names, the relevant registered enum descriptions, assembly and Impact zero-default rules, the seven established source navigation tools' key defaults/filters, and selected production/test/generated filtering. Not every supported default, cap, filter, scope, and target combination has public stdio evidence. `get_impact` maps zero-context Git hunk lines to innermost declarations, keeps same-line sibling declarators distinct, filters callers mode to externally visible methods/constructors, and retains discovered totals before `maxChangedSymbols` limits displayed entries.
- Public Git change-context tests use a temporary `.git`-file worktree and cover tracked unstaged edits, staged edits, untracked files, a path containing spaces and `ü`, same-line sibling declarations, mixed positive/deletion-only hunks, an entirely deleted source file, clean and non-Git status, and option-like/missing refs. Deletion-only hunks and unmapped files produce partial completeness rather than attributing a neighboring declaration. Git child-process cancellation and other unusual filename/rename cases remain unverified; lifecycle cancellation is tracked separately under point 9.4.
- Public byte/token recovery, domain truncation, continuation replay, and stale target/hash/generation behavior do not yet have a complete per-tool matrix. Focused early-error and zero-default cases above are verified; the complete byte/token retry and page-consumer matrix remains under point 8.5. `inspect_assembly` and `search_assembly` cursors are verified for their focused contracts; other tool cursors remain open. Large `find_symbol`, body, and assembly-context body results have been reconstructed across response-window pages with line-safe content; other large-response paths remain unverified.
- Cold single- and two-solution source fixtures verify workspace files, including `obj`/`bin`, remain unchanged before and after host exit, including two solutions with the same project name. Redirection of arbitrary MSBuild custom targets remains unverified.

The current registration and fixture evidence is recorded in the [Cluster 9.2 implementation record](../../tasks/AiNetLinter-Uebernehmen/Reviews/Cluster-09.md#point-92-git-change-context-hunk-and-status-slice--contract-work-open). Point 9.2 and dependent point 8.5 remain open until the remaining public contracts are implemented and tested.
