# MCP Navigation Registration Status

The production catalog exposes all twenty navigation tool names and two maintenance tools. The current real-stdio integration test exercises the thirteen handlers added for Cluster 9.2 on a deterministic source solution and a small managed assembly. That is implementation evidence for the listed paths, not acceptance of the full public reference contract.

## Exercised handler paths

The source fixture exercises `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, symbol-mode `get_impact`, Git `change-context`, file- and symbol-mode `dependency_graph`, source-handoff and SDK reference-pack `resolve_type_origin`, `get_feature_context`, and `get_test_context`. Core tests verify exact source project ownership for same-named declarations, plus production/test/generated filter-before-limit behavior and original-identity handoff roundtrips. The public dependency graph regression uses duplicate full type names, identical assembly names, and identical Roslyn project names at different project paths; it confirms symbol handoffs and exact or ambiguous file paths retain owner identity, and that source results print `Project.Name` instead of assembly identity. The same fixture exercises the source namespace project overview, ambiguous project/prefix choices, exact project-path drilldown, and a namespace type handoff through `get_symbol_body`.

The managed fixture exercises `get_assembly_context` with body, class structure, actual type-reference callers, impact, and a caller-handoff-to-body roundtrip; it checks detail-level validation, body truncation, a 512-byte explicit override, and blank symbol rejection. It also exercises `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, assembly `resolve_type_origin`, assembly symbol `get_impact`, assembly `get_file_tree` and `get_file_skeleton`, and `get_symbol_body` followups. Assembly `get_type_hierarchy` returns an actual `PagedBeta` subtype handle from the `PagedAlpha` hierarchy; `find_implementations` returns `PagedBeta` for `IBetaContract`. Both emitted handles are followed to the owning assembly body, and using either handle with a different managed target returns `TARGET_MISMATCH`. The owner-closure tests for find_references, call_tree, impact, and context additionally cover Root → B → C traversal at depth 1; broader assembly relationship and depth-2 closure remain open. The tree → skeleton → member handoff → body path is tested, and a neighboring DLL-folder sentinel is excluded. Source skeleton requests accept absolute files and a `../Shared` indexed compile include. A shared physical file included by two projects is ambiguous by path; a project-specific h selects the owner declaration file and its member h can be followed to the body. A namespace type handoff from the assembly target resolves to its body and class structure using the owning DLL path; passing a different managed DLL to `get_class_structure` returns `INVALID_ARGUMENT`. Public search cases verify automatic regex promotion, declaration-kind and C# file filtering, and matched-file `maxFiles` behavior: a nonmatching source file sorts before matching files, the capped scan returns real hits in one matched path, reports `truncatedBy=maxFiles`, and an uncapped query finds hits in multiple paths. Search domain pages are verified through the selected matched-file scope, including a nonmatching first file, multiple result lines in the selected file, hidden later matched files, and a final response that stays truncated by `maxFiles` without issuing another cursor. The public search cursor is bound to query, filters, target, root content, and resolved references; tests cover replay, wrong query/target, root replacement, and a separate Core regression for transitive reference replacement. Search results for types and methods include owner-bound handoffs; public type and method calls were followed through `get_symbol_body`, types through `get_class_structure`, and a foreign target was rejected. Qualified type lookup and public `maxFiles=0`/`maxResults=0` behavior are covered. A separate public stdio fixture emits A→B→C managed assemblies and checks the emitted PE references: A references B and B references C. Searching C through A reports C's canonical owner `targetPath`; that same handoff returns C's decompiled body with C as the requested target and produces `TARGET_MISMATCH` when A is supplied. Replacing C at the same path in the active host makes the old handoff return `STALE_SNAPSHOT`; a fresh search and handle return the replacement body. The test then deletes C while the same host is still active: a fresh Root search reports no C match with `unresolvedReferences` and truncated completeness, and using the old C handoff through the live Root target fails without stale text. Public body calls with only unknown identifiers return MCP errors; a mixed valid/unknown batch retains its successful body and reports truncated completeness. The source Git fixture is a linked worktree whose root contains a `.git` file. The Assembly inspection consumer follows response-window pages and retries a line-safe page with its advertised minimum byte budget when 512 bytes cannot contain the next complete line. A separate real stdio consumer runs `inspect_assembly` at `maxResults=1` through all domain pages, checks each type handoff ID appears once, reaches a complete final status, replays the first domain cursor, and verifies that changing `maxResults` rejects the old cursor.

The assembly type-relationship regression also follows an interface-method implementation, interface-property implementation, virtual method override, and virtual property override from their emitted owner handles to `get_symbol_body`. These cases use `get_class_structure` to select property handles because assembly `search_assembly` only advertises declaration handoffs for type and method matches.

## Current unverified contracts

- Core and public stdio tests verify transitive Root → B → C closure behavior. Core tests cover cursor invalidation and refreshed handoffs after missing/replaced C while the root PE stays unchanged; public stdio verifies owner-path routing, body roundtrip, stale handoff failure after replacement, fresh replacement body, and incomplete search/body errors after C is deleted in the live host. Assembly `get_type_hierarchy` and `find_implementations` are tested for root-decompiled source handles, member implementations/overrides, and cross-target rejection. Assembly `find_references(includeReferences=true)` scans referenced source at depth 1: a public C-owned method handle finds its B caller and C's own caller, and both handles roundtrip to canonical owner bodies. A type relationship also returns a B-owned type handle. Foreign handles fail, replaced-owner handles are stale, and depth 2 is explicitly truncated because cross-owner caller chaining is not composed. Assembly `get_call_tree(includeReferences=true)` merges owner-scoped source graphs, emits target paths for proven owner handles, maps outgoing metadata callees through their actual PE identity, and globally applies topN fanout after merging, then caps nodes and edges at 250. Duplicate edges retain distinct dispatch kinds. Incoming C.Read callers in B/C and outgoing B.Run → C.Read were followed to their correct bodies in ASCII and Mermaid; the Mermaid C-owner handoff also roundtrips to C body. Separate stdio cases assert global topN, both hard caps, and honest truncation. Depths above one remain incomplete because cross-owner call-chain expansion is not composed. Symbol-mode `get_impact(includeReferences=true)` scans bounded owner source at depth 1, preserves known aggregate totals when visible call sites are capped, and follows B/C caller handles to owner bodies. `get_assembly_context(includeReferences=true)` uses the same relationship scanners for Caller and Impact sections and preserves their depth-2 next-action reason; B.Run and C.LocalRun handles from both sections follow to owner bodies. Source and assembly `dependency_graph` are tested using exact symbol/file identities; edge endpoint handoffs follow to the correct source or assembly body, and foreign/source handles fail with `TARGET_MISMATCH`. Broader relationship closure remains open.
- `inspect_assembly` and `search_assembly` distinguish their bound `v1.<offset>.<binding>` domain cursors from the host's fixed-width decimal response-window page token. Outer byte/token pages still have their own immutable snapshot and must be completed before following the domain cursor carried by the payload. The full replay/error/budget matrix for every tool is not established.
- The full public parameter matrix remains open: exact defaults and caps, generated and production/test scopes on every applicable handler beyond the dependency graph and class-structure cases above, file and symbol targeting rules, stable pattern deduplication, source retry/error behavior, and the seven existing tools' reference default parity. `get_impact` now retains all documents sharing a physical path, but still needs hunk-level changed-symbol selection and honest Git scan completeness.
- Git change-context evidence covers a changed tracked source file in a temporary `.git`-file worktree. Statuses for malicious and missing refs, staged/unstaged/untracked/deleted files, non-Git and clean repositories, incomplete symbol mapping, and child-process cancellation have not been verified.
- Public byte/token recovery, domain truncation, continuation replay, and stale target/hash/generation behavior do not yet have a complete per-tool matrix. `inspect_assembly` and `search_assembly` cursors are verified for their focused contracts; other tool cursors and exact small-positive token recovery remain open. Larger body and find results have not been verified for line-safe rendering without escaped monolithic JSON.
- A cold source fixture verifies no workspace writes. Same-project-name isolation across two solutions and external MSBuild target redirection remain unverified.

The current registration and fixture evidence is recorded in the [Cluster 9.2 implementation record](../../tasks/AiNetLinter-Uebernehmen/Reviews/Cluster-09.md#point-92-registered-handler-slice--contract-work-open). Point 9.2 and dependent point 8.5 remain open until the remaining public contracts are implemented and tested.
