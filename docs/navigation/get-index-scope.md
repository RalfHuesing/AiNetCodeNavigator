# Index Scope

`IndexScopeScanner.ScanAsync` reports the Roslyn document inventory for a loaded solution or one named project. It reads project and document metadata. For C# documents it also reads source text and syntax/semantic information to apply the same generated-source classifier used by symbol navigation. It does not access the filesystem or change workspace contents. Documents with compile errors remain in the inventory.

The scope includes each project's Roslyn `Project.Documents` entries, including documents from non-C# projects. `TotalDocumentCount` and file-type counts describe these document entries, not unique physical files or every asset under a project directory. `CSharpFileCount` counts `.cs` document entries belonging to C# projects. `GeneratedDocumentCount` counts C# documents recognized by symbol navigation as generated: `obj/` paths, `.g.cs`, `.g.i.cs`, `.generated.cs`, or `.designer.cs` suffixes, `<auto-generated` in the first five lines, or a `GeneratedCodeAttribute` on a declaration. `TestDocumentCount` counts documents whose project is classified as a test project or whose path is classified as a test file, matching symbol navigation's `all`/`production`/`tests` scope classification. Each project entry reports its document count, C# document count, language classification, and test-project classification. File-type entries indicate symbol navigation coverage only when all `.cs` entries of that extension belong to C# projects.

Project names are matched case-insensitively. An unknown project returns `ScanCompleted=false` and an `Error`; cancellation is propagated to the caller. The Core scanner retains its default bounds of 100 projects and 64 file types, with caps of 500 and 128. The MCP handler collects the complete loaded inventory, applies the public `maxResults` page size (default 100, range 1–128) to the combined project and file-type stream, and exposes a `resultCursor` until every discovered entry is reachable. Project identity combines the canonical project path and the loaded framework context; if the workspace does not expose a loaded TFM, the context is explicitly `unknown`. The loaded snapshot also carries the evaluated configured framework list from its MSBuild structure inputs. Each project entry reports `configuredFrameworksKnown`; when true, `configuredFrameworksNotAnalyzed` lists configured frameworks absent from every loaded context for the same canonical project path. A false availability flag means no configured-framework claim is made. The scope tool reports loaded contexts and does not analyze additional frameworks. `Exclusions` names documents excluded by default navigation, such as generated source; test classification is reported separately and is not treated as an exclusion. Scope filters and document enumeration happen before paging.

Every MCP scope inventory page retains a target-wide framework-coverage summary calculated from the complete discovered project inventory before paging. It counts project entries with known configured frameworks not analysed and entries with unknown configured-framework coverage, and points to project items for exact framework names and loaded contexts. Counts describe loaded project entries, including separate loaded contexts for the same project path, rather than unique project files. Zero missing entries does not establish complete configured coverage when unknown entries exist; an empty inventory reports zero entries in both categories. The summary uses existing inventory facts and does not evaluate or load additional frameworks.

The Core inventory describes the loaded Roslyn `Project.Documents` scope used by navigation. Materialized source-generated documents can be searched and navigated by symbol tools, but they are separate from the regular document inventory and are not counted here. Physical non-C# project assets and generated/build file categories outside that loaded scope are not part of this scanner.

The MCP host registers `browse_target` with `view=scope` for source solution targets only. The public SDK method accepts `maxResponseBytes` (512–65,536; default 16,384), optional positive `maxResponseTokens`, `operationToken` for polling background work, `continuationToken` for immutable outer response pages, and `resultCursor` for the completed inventory. Budget changes affect outer page formatting but do not change the selected query or snapshot. Its snapshot identity adds the evaluated configured-framework inventory to the source-analysis fingerprint, so it is stable for the same loaded inventory and distinct from ordinary source-navigation snapshot IDs. It reports configured frameworks absent from loaded contexts; it does not analyze them. A transport-free SDK/validator contract test reconstructs outer pages, follows all combined inventory pages, and reloads the same SDK workspace in a second runtime to verify stable project identity and the actual `net10.0` context. Cancellation is handled by the host and is not a wire parameter. See [Shared Symbol Resolution](symbol-resolution.md), [MCP Host](../mcp-host.md), and [MCP Long-Running Calls and Continuations](../mcp-long-running-calls.md).

The scope response states `view=scope` and `inventory=loadedRoslynDocuments`. Project entries include their canonical `projectPath` separately from `projectIdentity`; use the path unchanged as the namespace view's project selector. It is an evaluated project owner, not a disk file inventory. Namespace-only options are rejected, including explicitly supplied defaults. The scope branch never invokes namespace traversal, and its cursor binds the selected view and original argument presence as well as its distinct inventory snapshot.
