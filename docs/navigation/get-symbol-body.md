# Get Symbol Body

`SourceSymbolBodyResolver.Resolve` extracts the source declaration associated with a Roslyn symbol. The identifier-based `ResolveAsync` first uses the [shared symbol resolution contract](symbol-resolution.md); unresolved or ambiguous identifiers return a structured error and, for ambiguity, selectable candidates. The body result contains declaration text, source availability, total line count, displayed one-based line bounds, truncation state, documentation ID, and an optional stable reference. A partial method definition with an implementation resolves to the implementation declaration. Default interface methods with executable bodies remain available; abstract methods and properties, abstract interface members, and interface declarations report unavailable bodies.

`maxBodyLines` limits the output window and `startLine` selects its one-based starting line. Values below one are normalized to one. A window that exceeds the declaration returns a message with the total line count and does not throw. Truncated windows include a continuation marker and set `HasMore`. Each successful MCP item reports `Resolution status: resolved`, its displayed line interval, and either a complete-window action or its own next `startLine` and `maxBodyLines`. Continue with that item's reference, omit `endLine`, and read every outer response page before requesting the next body window; this keeps the next interval executable even when the first request used an explicit `endLine`. Each follow-up resolves the current declaration text; windows from different reported snapshots do not form one consistent body.

`ResolveBatch` applies the same window to each input symbol, preserves input order, and returns an empty result for an empty sequence. Metadata symbols without source syntax are retained as unavailable results with zero source lines, so they do not prevent other batch items from being returned. Passing a null symbol or null batch sequence throws `ArgumentNullException`.

The MCP host registers `get_symbol_body` for source and managed-assembly targets. Assembly references from referenced assemblies must be called with the owner `targetPath` printed by the producer. Every item reports its own resolution status and recovery action. A mixed batch retains successful bodies and includes the failure code, hint, and rediscovery action for each failed item; an all-failed batch remains an MCP error while preserving details for every requested item. Reference resolution errors use `INVALID_SYMBOL_REFERENCE`, `TARGET_MISMATCH`, `SYMBOL_NOT_FOUND`, `AMBIGUOUS_SYMBOL`, or `UNSUPPORTED_IDENTIFIER`; retained page or replaced-generation evidence can still report `STALE_SNAPSHOT`. Recovery follows the per-item action and rediscovers a declaration after rename, signature change, or absence. Assembly batches retain the existing owner generation lease for their duration. Source and assembly handler contracts exercise body windows, mixed-success and all-failed batches, and byte/token projections. See [MCP Host](../mcp-host.md) for the public catalog and [Shared Symbol Resolution](symbol-resolution.md) for reference behavior.

Each successful body item keeps its exact input selector when it differs from the stable `handoffId`; when the input bytes already equal the handoff, the repeated `Symbol` line is omitted. The handoff and exact owner target remain available for follow-up. Body availability and content mode remain explicit, and a nonempty unavailable-body hint is shown. Only incomplete windows include a next-window action; a complete window is identified by its line summary without a no-action sentence. Assembly batches also show the absolute `Decompiled source root` once when the acquired owner context provides one.

For a managed-assembly target, the body tool also accepts a raw declaration name, documentation ID, `path:line`, or `path:line:column` within that target's decompiled source. A raw success returns its stable reference when the declaration has a unique canonical identity, alongside the canonical owner `targetPath`; callers can use that reference in another assembly consumer. If no reference is representable, the body and raw location remain available without claiming a stable follow-up. A source reference passed to an assembly target returns `TARGET_MISMATCH`.
