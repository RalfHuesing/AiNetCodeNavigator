# Get Type Hierarchy Core Engine

`TypeHierarchyScanner.ScanAsync` accepts a Roslyn class, interface, or struct symbol and reports its full base type chain and transitive implemented interfaces. Every source declaration location for a partial base type or interface gets its own entry with a relative path, one-based line, and project-aware stable reference when an exact identity is available. Metadata-only bases and interfaces remain visible as one entry with no source path or reference.

For classes, the scanner returns direct and indirect derived classes across the solution. For interfaces, it returns direct and indirect implementing types across the solution, including classes that inherit an implementation. Structs retain their base and interface information and have no derived-class search. Subtypes are represented once per type even when the subtype is partial; base/interface source locations and subtype entries are ordered deterministically.

Core `maxResults` applies only to derived or implementing subtypes and is normalized to at least one. At the MCP handler, the same positive argument is the page size for the complete discovered subtype list, while base types and interfaces remain on each page. The public query and inner cursor binding both include `maxResults`; changing the page size while continuing a cursor returns `RESULT_CURSOR_ARGUMENT_MISMATCH`. `resultCursor` resumes the list for the same target, snapshot, filters, page size, and result section. Inheritance cycles in malformed source are stopped by tracking each base type's original definition; cancellation is checked during base-chain traversal and Roslyn subtype searches. Any Core traversal truncation remains separate from page availability.

Null symbols and solutions throw `ArgumentNullException`. Enums and other unsupported named type kinds return a payload with `IsSuccess == false` and an explanatory `ErrorMessage`; the formatter returns that error text. A supported type with no subtypes is a successful result with an empty list. The text formatter renders the base chain with indentation, interfaces as a list, and derived or implementing types in the bounded final section. The public handler supports `scopeType` (`all`, `production`, or `tests`) and `includeGenerated` (false by default), applying them before subtype totals and limits while retaining original solution identity in source references. Assembly targets resolve references only against the supplied owner; declarations proven to come from the selected assembly's materialized source receive assembly references, while metadata-only bases/interfaces receive no invented source reference. The hierarchy route remains scoped to the selected assembly's decompiled source and does not traverse referenced-assembly source. See [Shared Symbol Resolution](symbol-resolution.md) for reference lifetime and owner rules.
