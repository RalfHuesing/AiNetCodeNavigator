# Find References and Implementations Core Engines

`FindReferencesResolver` uses Roslyn's solution-wide symbol reference search. The legacy overload searches direct references (depth 1); the depth overload follows caller symbols breadth-first, with depth clamped to 1–3 and a hard cap of 200 expanded symbols. A lower `maxNodes` value can narrow the node budget; higher values are clamped to 200. Each source location includes its relative file path, one-based line and column, source snippet, project name, enclosing symbol name, depth, and the symbol whose references were searched. When a canonical source identity is available, both the enclosing and reached-from symbols include opaque `h:` handoffs that resolve to declarations in the correct project. Visited symbols are de-duplicated to stop cycles.

`FindImplementationsResolver` behavior is provided by `FindReferencesResolver.FindImplementationsAsync`. For interface types it returns implementing types across the solution; for classes it returns direct and indirect derived types. For interface methods it returns implementing members, and for virtual, abstract, or override methods it returns overrides. Entries include a source location, signature, project name, and an opaque source handoff when available.

Both resolvers sort results deterministically and normalize `maxResults` to at least one. Reference and impact sites use the same source-location identity and ordering keys, including project, path, line, column, caller, and reached-from symbol identity. Separate calls on one line remain separate entries in both results. `FindReferencesResult.TotalCount` counts discovered call sites before the display limit; `IsTruncated` reports display-limit truncation, while `IsTruncatedByNodeLimit` and `IsDepthClamped` report traversal limits. `IsComplete` is false when any of these limits prevent the requested traversal. `EffectiveNodeLimit` reports the applied node cap. `FindImplementationsResult.TotalCount` reports the full number of implementations before limiting and `IsTruncated` reports display-limit truncation. Unsupported implementation targets (such as structs and non-virtual concrete methods) return an empty result with `IsSuccess == false` and an explanatory `ErrorMessage`; a supported symbol with no results returns `IsSuccess == true`. Null symbols and solutions throw `ArgumentNullException`; a node limit below one throws `ArgumentOutOfRangeException`. Cancellation is passed through Roslyn searches and checked while collecting locations.

These Core APIs take an already-resolved Roslyn symbol, so unknown names, ambiguous identifiers, and invalid or stale handoffs are reported by the shared symbol-resolution layer before calling them. The public handlers accept `scopeType` (`all`, `production`, or `tests`) and `includeGenerated` (false by default). They filter source locations before totals and result limits, and real stdio source paths are exercised. Assembly targets for `find_implementations`, `find_references`, and `get_call_tree` resolve owner-bound assembly handles and reject foreign targets. Public tests follow an interface type implementation, interface method implementation, interface property implementation, virtual method override, and virtual property override to the owning assembly body. They also follow an incoming reference and incoming/outgoing call-tree node from `BetaInvoker.Invoke` to its body, and an impact caller location from `PagedBeta.ReadBeta` through `BetaInvoker.Invoke` to its body. A genuine source-origin handoff sent to an assembly relationship route returns `TARGET_MISMATCH`.

For assembly `find_references`, `includeReferences=true` scans the bounded resolved reference closure at depth 1. Each returned assembly location includes its owner's canonical `ownerTargetPath`, so the matching handle can be passed to an owner-aware follow-up. The public Root → B → C regression passes a C-owned method handle to a search rooted at A, verifies the actual B caller, and follows both B's caller handle and C's own caller handle to their canonical owner bodies. A type reference also resolves to the declaring B type. Foreign owner handles are rejected, same-path replacement makes prior handles stale, and depth 2 is explicitly marked incomplete because cross-owner caller chaining is not composed. For source results, duplicate elimination retains `Document.Project.Id` as an internal owner key, so linked documents from projects with identical names, assembly names, and symbol IDs remain separate; stable ordering uses the owning project path. Handoffs are generated only after the visible locations are selected. Assembly `get_call_tree` and symbol-mode `get_impact` still report their root-only result as truncated when `includeReferences=true`; `get_assembly_context` does not scan caller or impact sections through referenced assemblies. The wider relationship matrix and full public default/budget parity remain open. See [MCP navigation registration status](mcp-registration-status.md).
