# Find References and Implementations Core Engines

`FindReferencesResolver` uses Roslyn's solution-wide symbol reference search. The legacy overload searches direct references (depth 1); the depth overload follows caller symbols breadth-first, with depth clamped to 1–3 and a hard cap of 200 expanded symbols. A lower `maxNodes` value can narrow the node budget; higher values are clamped to 200. Each source location includes its relative file path, one-based line and column, source snippet, project name, enclosing symbol name, depth, and the symbol whose references were searched. When a canonical source identity is available, both the enclosing and reached-from symbols include opaque `h:` handoffs that resolve to declarations in the correct project. Visited symbols are de-duplicated to stop cycles.

`FindImplementationsResolver` behavior is provided by `FindReferencesResolver.FindImplementationsAsync`. For interface types it returns implementing types across the solution; for classes it returns direct and indirect derived types. For interface methods it returns implementing members, and for virtual, abstract, or override methods it returns overrides. Entries include a source location, signature, project name, and an opaque source handoff when available.

Both resolvers sort results deterministically and normalize `maxResults` to at least one. Reference sites use the same ordering keys as impact sites, including project, path, caller, and reached-from symbol identity; call sites on one source line reached from different symbols remain separate and ordered consistently. `FindReferencesResult.TotalCount` counts discovered call sites before the display limit; `IsTruncated` reports display-limit truncation, while `IsTruncatedByNodeLimit` and `IsDepthClamped` report traversal limits. `IsComplete` is false when any of these limits prevent the requested traversal. `EffectiveNodeLimit` reports the applied node cap. `FindImplementationsResult.TotalCount` reports the full number of implementations before limiting and `IsTruncated` reports display-limit truncation. Unsupported implementation targets (such as structs and non-virtual concrete methods) return an empty result with `IsSuccess == false` and an explanatory `ErrorMessage`; a supported symbol with no results returns `IsSuccess == true`. Null symbols and solutions throw `ArgumentNullException`; a node limit below one throws `ArgumentOutOfRangeException`. Cancellation is passed through Roslyn searches and checked while collecting locations.

These Core APIs take an already-resolved Roslyn symbol, so unknown names, ambiguous identifiers, and invalid or stale handoffs are reported by the shared symbol-resolution layer before calling them. MCP transport formatting and public tool errors are covered by later tool-integration work.
