# Dependency Graph Core Scanner

`DependencyGraphScanner.ScanSolutionAsync` reports declared project references plus namespace and file edges inferred from source type usages in the solution. A file or namespace edge carries both project names so identical relative file paths or namespace names in different projects remain distinguishable. Type declarations are keyed by Roslyn symbol identity, including assembly identity; two projects can therefore define the same fully qualified type name without cross-wiring the reported target. Partial source types use their lexically first solution-relative declaration path as the representative file.

External metadata types, including BCL and package types, do not create namespace or file edges. Only types with source declarations in the scanned solution are represented. Project references are reported independently of whether a source type edge was found.

The scanner processes documents in deterministic project-name and path order. `MaxDocuments` defaults to 1000 and is capped at 1000; reaching that cap sets `DocumentLimitReached`. `PageSize` defaults to 100 and is capped at 500. `Offset` and `PageSize` are validated (`Offset >= 0`, `PageSize >= 1`); `MaxDocuments` must also be at least one. A negative offset or nonpositive size throws `ArgumentOutOfRangeException`, a null solution throws `ArgumentNullException`, and cancellation propagates.

Each relationship collection is paged independently with the same offset and page size. The `Total*DependencyCount` fields describe the complete relationship set for the scanned documents, while each `HasMore*Dependencies` field indicates additional pages for that collection. `IsTruncated` is true when any collection has another page, the document scan hit its limit, or a document could not be analyzed. `IsComplete` is false when the document cap was reached or `Errors` contains a recoverable document issue. Errors identify the project and document and leave successfully analyzed documents in the result. `PageSizeWasClamped` and `DocumentLimitWasClamped` record requested limits reduced to their hard caps.

The scanner does not implement the AiNetLinter tool's target-file/type traversal, direction, production/test scope, generated-file filtering, or handoff rendering. Those belong to the later tool integration layer; this Core API is a bounded solution-wide graph snapshot.
