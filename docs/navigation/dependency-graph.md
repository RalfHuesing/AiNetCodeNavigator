# Dependency Graph Core Scanner

`DependencyGraphScanner.ScanSolutionAsync` reports declared project references plus namespace, file, and type edges inferred from source type usages. File and namespace edges carry both project names, so identical relative paths or namespace names in different projects remain distinguishable. `TypeDependencies` preserves the source and target type IDs and names, projects, files, and traversal depth. Type IDs include assembly identity and the canonical owning project path, so identical metadata names and assembly names in different projects remain separate graph nodes.

The scanner recognizes identifier, generic, and qualified type syntax through Roslyn semantic symbols. External metadata types, including BCL and package types, do not create namespace, file, or type edges. Partial source types use the syntax location containing the reference to retain the relevant source file. The public MCP response adds stable references only to visible edges whose exact declaration identity is available.

Documents are processed in deterministic project-name and path order. `MaxDocuments` defaults to 1000 and is capped at 1000. `DocumentOffset` selects the first document in a batch; `NextDocumentOffset` is the cursor for the next call. `IsComplete` is true only when a response starts at offset zero and covers the remaining document list without errors or depth clamping. Later cursor pages stay marked partial because the Core API does not retain prior batches; callers can aggregate their type edges and verify that the final cursor is null. An offset past the end throws `ArgumentOutOfRangeException`.

`ScanSolutionAsync` orchestrates `ValidateOptions`, `SelectDocumentsAsync`, `GetProjectDependencies`, `CollectTypeReferencesAsync`, and `CreatePayload`. Semantic scanning reuses a per-project compilation cache within the selected document batch; `CollectDocumentTypeReferencesAsync` handles each document's source and semantic references. Target traversal remains between collection and result projection.

`TargetFilePath` and `TargetTypeName` select a source file or fully qualified type as the traversal center; they are mutually exclusive. The Core API also accepts project-qualified `TargetTypeId`/`TargetTypeIds` to select exact Roslyn symbols. The MCP `dependency_graph` handler resolves a source or assembly reference to that exact type identity and resolves a file path to one exact document before scanning; a relative path that matches multiple documents returns a typed argument error. Source symbol results report the owning Roslyn `Project.Name`; dependency node identity remains bound to the canonical project path so same-named projects do not collapse. For an assembly target, symbol and file scans are restricted to its materialized decompiled source; edge endpoint references identify the verified assembly owner. Metadata nodes without a verified owner receive no assembly reference. `Direction` is `Outgoing`, `Incoming`, or `Both`. `Depth` is clamped to 1–3 and the result exposes requested/effective depth and `IsDepthClamped`. Each edge keeps the source type, so callers in the same file remain distinct. A targeted `ScanSolutionAsync` call traverses only its current document batch; while `NextDocumentOffset` is present, results are partial and `IsComplete` is false. See [Shared Symbol Resolution](symbol-resolution.md) for owner coordinates.

For target traversal across document batches, scan each batch without target filters and pass every document and relationship page to `DependencyGraphTraversal.MergeAndTraverse`. The merger checks cursor continuity, combines direct type edges across batches, then applies the target, direction, and depth to the merged graph. Missing document or relationship pages set `ContinuationInputIncomplete` and keep `IsComplete` false. Traversal visits at most 200 types by default (`MaxNodes`), with a hard cap of 200; `VisitedTypeCount`, `NodeLimitReached`, and `HiddenTypeDependencyCount` describe the cutoff. A node cap or depth clamp keeps `IsComplete` false.

The public source `dependency_graph` handler drains all 1000-document source windows and all 500-edge relationship windows internally for the requested traversal, then projects only the visible edges and assigns source references when their exact identities are available. This does not add a public cursor or change the Core scanner's one-batch contract. Direct-handler contracts cover budget-limited responses, targeted documents, exact file and symbol selectors, and project-bound same-named generic types.

Relationship collections use a shared `Offset` and `PageSize` cursor; page size defaults to 100 and is capped at 500. A shorter collection returns an empty list in later shared pages after its total has been covered. `MergeAndTraverse` checks continuity of the shared page windows and each collection's expected item count, so a complete type-edge continuation remains complete even when, for example, project edges ended on the first page. Missing a shared page still sets `ContinuationInputIncomplete`. `Offset` must be nonnegative, `PageSize` and `MaxDocuments` must be positive, and a null solution throws `ArgumentNullException`. Cancellation propagates. The `Total*DependencyCount` values describe the relationship set for the current document batch, and the `HasMore*Dependencies` fields indicate additional relationship pages. `IsTruncated` and `IsComplete` also account for a nonzero relationship offset, document batches, depth or node limits, missing merge input, and document errors. Recoverable errors identify the project and document while retaining successfully analyzed results. Clamp metadata records page or document limits reduced to their hard caps.

`ScopeType` filters production or test documents before document limits and counts are applied. Generated documents are excluded by default and included when `IncludeGenerated` is true. The MCP handler supplies these filters from the public `scopeType` and `includeGenerated` arguments. Public stdio coverage exercises duplicate type names with identical assembly names in separate projects, exact file selection, ambiguous short paths, generated inclusion, and production/test scopes.
