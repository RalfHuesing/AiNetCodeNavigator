# Get File Skeleton

`FileSkeletonBuilder.BuildMarkdownForDocumentAsync` renders the top-level type declarations in one C# source document. The underlying `SkeletonMapBuilder.BuildForDocumentAsync` returns structured `SkeletonTypeInfo` and `SkeletonMemberInfo` records for classes, records, interfaces, structs, and enums. Nested type declarations are intentionally omitted, matching the navigation reference.

Type and member entries include their declaration kind, modifiers, signature, relative source path, and an optional stable reference. The syntax walker reads declarations from Roslyn syntax and semantic models; method and constructor bodies are not included in the skeleton. Field and event initializers are omitted as well, so initializer lambdas and block expressions cannot leak implementation bodies into the result. Each variable in a multi-variable field or event declaration is emitted separately with its own reference when representable. Record primary-constructor parameters are represented as synthesized properties, and enum values are represented as fields.

The Markdown renderer groups types by namespace and includes a reference when one is available. Reference creation and unavailable-declaration behavior follow the [shared symbol resolution contract](symbol-resolution.md). Null documents, paths, projects, type lists, or semantic models are rejected with `ArgumentNullException`. A document without a syntax tree or semantic model produces an empty type list; cancellation is propagated.

The MCP host registers `get_file_skeleton` for source and managed-assembly targets. A source reference in `filePaths` resolves to every declaring regular or generated document in its exact loaded owner, including partial declarations; this tool has no scope/generated-source filter. Physical paths keep their existing solution-relative interpretation. Source path requests can also resolve indexed absolute paths and linked documents outside the solution directory; basename or suffix matches must identify exactly one document. Assembly paths resolve only inside the selected target's materialized decompiled source tree. An assembly reference can select its declaration file. Linked source files with multiple project owners are reported as ambiguous instead of selecting an arbitrary project. Source and assembly handler contracts cover references, missing-file errors, response budgets and outer-page reconstruction. See [MCP Host](../mcp-host.md).

The file skeleton route has no separate result-list cap or domain cursor: each selected file is rendered as a complete declaration outline, with large text responses continued through immutable outer `continuationToken` pages. A source batch is analyzed from one leased solution snapshot; an assembly batch holds one pinned assembly scope. Successful skeletons remain visible when another requested path or reference fails, and that mixed result reports incompleteness.
