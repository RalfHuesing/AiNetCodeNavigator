# Get File Skeleton

`FileSkeletonBuilder.BuildMarkdownForDocumentAsync` renders the top-level type declarations in one C# source document. The underlying `SkeletonMapBuilder.BuildForDocumentAsync` returns structured `SkeletonTypeInfo` and `SkeletonMemberInfo` records for classes, records, interfaces, structs, and enums. Nested type declarations are intentionally omitted, matching the navigation reference.

Type and member entries include their declaration kind, modifiers, signature, relative source path, and an optional handoff ID. The syntax walker reads declarations from Roslyn syntax and semantic models; method and constructor bodies are not included in the skeleton. Field and event initializers are omitted as well, so initializer lambdas and block expressions cannot leak implementation bodies into the result. Each variable in a multi-variable field or event declaration is emitted separately with its own symbol handoff. Record primary-constructor parameters are represented as synthesized properties, and enum values are represented as fields.

The Markdown renderer groups types by namespace and includes an `h:...` handoff ID when one is available. `FileSkeletonBuilder` creates opaque source handoffs by default. A caller may provide `formatSymbolId` to control how raw documentation IDs are exposed; the formatter is applied separately to every field and event variable, including later variables from a shared declaration. Null documents, paths, projects, type lists, or semantic models are rejected with `ArgumentNullException`. A document without a syntax tree or semantic model produces an empty type list; cancellation is propagated.

The MCP host registers `get_file_skeleton` for source and managed-assembly targets. Source requests resolve paths against indexed documents, including absolute paths and linked documents outside the solution directory; basename or suffix matches must identify exactly one document. Assembly requests resolve paths only inside the selected target's materialized decompiled source tree. Linked files with multiple project owners are reported as ambiguous instead of selecting an arbitrary project. The transport-free source handler contract verifies distinct handoffs for variables in one field declaration, a missing-file error, and reconstruction of a response requiring multiple outer continuation pages under byte and token caps. Public stdio coverage follows an assembly `get_file_tree` path through its skeleton and a member handoff to `get_symbol_body`, and covers mixed-valid and all-invalid file lists. See [MCP Host](../mcp-host.md).
