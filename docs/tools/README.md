# MCP Tools

The server registers 19 read-only navigation tools. Their SDK method definitions are the authority for wire names, descriptions, defaults, and validation; this page explains how to choose and use them. Targets are absolute paths: source tools require an existing `.sln` or `.slnx`, and assembly tools require a managed `.dll` or `.exe`. Assembly navigation uses the selected binary's decompiled source and supported owner references; it never executes analyzed binaries. `get_index_scope`, `get_feature_context`, and `get_test_context` are source-only.

## Shared request and response behavior

Unless a tool row says otherwise, `maxResponseBytes` is a hard UTF-8 text limit from 512 through 65,536 bytes and `maxResponseTokens` is an optional positive hard limit counted with `cl100k_base`. Each tool has its own documented byte default. Budgets constrain successful output and recoverable errors; the server does not silently raise them. If a result cannot fit, retry the same request at the exact `minimumResponseBytes` and `minimumResponseTokens` pair in `RESPONSE_BUDGET_TOO_SMALL`; the offered byte minimum is at least the public 512-byte floor. Do not change the query between attempts. A token limit too small to encode even the recovery envelope returns sanitized `InvalidParams`.

Navigation calls that can load a target accept `operationToken`. When a response says `operation=running`, repeat the same tool and query with that token to poll. The host waits at most 15 seconds per response window; cancellation of a poll only stops that wait, while cancellation of the first request cancels its owned work. Budgets and tokens do not change the operation's query identity. Do not combine an operation token with an outer-page token.

Text too large for one response window is stored as immutable response pages. Follow the `continuationToken` shown in the response preamble by repeating the same query with that token. These outer pages are independent of any domain cursor included in the result. For `inspect_assembly` and `search_assembly`, read every outer response page first, then use the opaque assembly `resultCursor` with the same target and filters. It is tied to the analyzed assembly owner/reference snapshot and result section. The preamble separates `analysisCompleteness` and concrete `omissions` from `resultContinuation`; a result page can be complete for its snapshot while advertising another domain page. Other bounded tools report domain truncation and a next action; they do not offer a domain cursor.

Symbol producers return opaque `h:...` handoffs when the owning source snapshot or assembly generation can be identified. Pass a handoff unchanged to its consumer; do not parse it or substitute a display name. Handoffs from a disposed host runtime are unknown. If a tool reports truncation, follow its `nextAction` or repeat the same query with the indicated domain limit changed. Body windows use one-based inclusive source/decompiled lines.

## Navigation tools

| Tool | Purpose and targets | Wire arguments and notable behavior |
|---|---|---|
| `find_symbol` | Find matching C# declarations in source or managed assemblies. | `targetPath`; exactly one of `pattern` or `namePatterns` (1–10 non-empty patterns); optional `kind`; source `scopeType` (`all`), `includeGenerated=false`; `maxResults=50` per pattern (1–1000); `includeReferences=false` for resolved assembly owners (ignored for source); `operationToken`, `continuationToken`; bytes default 16,384. Results include owner and usable handoffs where available. |
| `get_symbol_body` | Read source or decompiled declarations in target order. | `targetPath`, required non-empty `symbolIdentifiers`; optional `maxBodyLines=80` per identifier (1–1000), one-based `startLine=1`, inclusive `endLine`; operation/page tokens; bytes default 32,768. Names, documentation IDs, source locations, and current handoffs are accepted. A mixed valid/invalid batch retains valid bodies and reports truncation; an all-invalid batch is an error. |
| `get_file_skeleton` | Show declaration outlines without bodies or executable initializers. | `targetPath`, required `filePaths` (indexed relative/absolute source paths, or handoffs identifying declaration files); operation/page tokens; bytes default 24,576. Source paths must resolve inside the indexed solution; assembly paths refer only to the selected binary's decompiled source. Multi-variable declarations get separate handles. |
| `get_class_structure` | List declared members and signatures for a type. | `targetPath`, required `symbolIdentifier`; `sortBy=lines` (`kind` or `name` also supported); `maxMembers=50` (1–200, page size); optional `kindFilter`, `nameFilter`; source `scopeType=all`, `includeGenerated=false`; operation, outer-page, and result cursors; bytes default 16,384. The `lines` order is file path, declaration line, then name. All discovered filtered members are reachable through `resultCursor`. Assembly scope filters do not classify assembly members as production/tests. Member handles can be passed to `get_symbol_body`. |
| `get_namespace_tree` | Browse namespace and type declarations, optionally scoped to a project. | `targetPath`; optional exact `project` name or canonical path and `namespacePrefix`; `depth=1` (1–3); `includeTypes=true`; `kind=all` (`class`, `interface`, `record`, `struct`, `enum`); `maxResults=50` (1–200, page size); `includeGenerated=false`; operation, outer-page, and result cursors; bytes default 16,384. Use the full project path to disambiguate same-named projects. The combined project, namespace, and type inventory remains reachable through `resultCursor`; depth is an analysis bound. |
| `get_index_scope` | Summarize the loaded Roslyn solution's indexed project/document scope. | Source-only `targetPath`; `maxResults=100` (1–128, page size); operation, outer-page, and result cursors; bytes default 16,384. It reports loaded project identity and framework context, indexed document scope, C# navigation coverage and generated/test classifications; it is not a complete physical-file inventory or a scan of every configured TFM. Use external file search for physical files or assets outside the loaded solution scope. |
| `get_call_tree` | Trace incoming, outgoing, or combined calls in source or assembly owners. | `targetPath`, required `symbolIdentifier`; `direction=incoming` (`outgoing`, `both`); `depth=2` (1–5); `topN=10` (1–250); `format=ascii` (`mermaid`); `includeBcl=false`; source `scopeType=all`, `includeGenerated=false`; `includeReferences=false`; assembly `includeDiagnostics=false`; operation/page tokens; bytes default 32,768. Graph node, edge, and fanout caps produce truthful domain truncation, not a cursor. |
| `find_references` | Find direct/transitive uses with location, dispatch, provenance, and owner. | `targetPath`, required `symbolIdentifier`; `depth=1` (1–3); `maxResults=50` (positive page size); source `scopeType=all`, `includeGenerated=false`; `includeReferences=false` for supported assembly owner closure; operation, outer-page, and result cursors; bytes default 16,384. Depth, node, and owner-closure limits describe analysis coverage separately from pages. |
| `get_type_hierarchy` | Show bases, interfaces, derived types, and partial declarations. | `targetPath`, required `symbolIdentifier`; `maxResults=50` (positive subtype page size); source `scopeType=all`, `includeGenerated=false`; operation, outer-page, and result cursors; bytes default 16,384. Assembly traversal covers the target's own decompiled source; it does not add a referenced-assembly closure option. |
| `find_implementations` | Find interface, abstract/virtual member, and override implementations. | `targetPath`, required `symbolIdentifier`; `maxResults=50` (positive page size); source `scopeType=all`, `includeGenerated=false`; operation, outer-page, and result cursors; bytes default 16,384. Unsupported target symbols return a recoverable input error. Assembly result handles retain their owning target. |
| `get_impact` | Summarize callers and affected projects for one source or assembly symbol. | `targetPath`, required non-empty `symbolIdentifier`; `depth=1` (1–3); `maxResults=50` (positive call-site page size); `includeReferences=false`; operation, outer-page, and result cursors; bytes default 16,384. Traversal depth/node/owner limits remain analysis bounds. Git refs, changed files, and change-context arguments are not part of this tool. |
| `dependency_graph` | Traverse file or symbol dependency edges across source or supported assembly scope. | `targetPath`; exactly one of `filePath` or optional `symbolIdentifier`; `direction=both` (`incoming`, `outgoing`); `depth=1` (1–3); `maxResults=50` (1–500); source `scopeType=all`, `includeGenerated=false`; operation/page tokens; bytes default 24,576. Project-qualified identities preserve same-named types in different projects. |
| `resolve_type_origin` | Resolve a type to its source declaration or metadata/framework/NuGet assembly. | `targetPath`; exactly one non-empty `symbolIdentifier` or `typeName`; operation/page tokens; bytes default 16,384. Output preserves source project or DLL identity and can report ambiguous candidates. |
| `get_assembly_context` | Combine an assembly overview with selected body, structure, caller, or impact sections. | Assembly `targetPath`; optional `symbolIdentifier`; `includeReferences`, `includeCallers`, `includeImpact`, `includeBody`, `includeClassStructure` (all false); `maxResults=100` (0 also means 100, maximum 1000); `maxBodyLines=80` (1–1000); `maxCallers=10`, `topN=10` (1–200); `depth=1` (1–3); `detailLevel=standard` (`compact`, `full`); optional `maxResponseBytes` (0/omitted: compact or standard 32,768, full 65,536; a positive value overrides); token and outer-page tokens. Errors in a requested section remain errors, not partial success. |
| `inspect_assembly` | Inspect public API declarations and filter types, members, or namespaces. | Assembly `targetPath`; optional `namespace`, `typeName`, `memberName`; `publicOnly=true`, `exactTypeName=false`, optional `memberNames`; `maxResults=100` and `maxMembers=100` (zero normalizes to 100; max 1000 each); optional `includeReferences` (when omitted, references are included unless a type/member filter narrows the query); `detailLevel=standard`; `maxResponseBytes=24,576` (zero also selects 24,576); `maxResponseTokens`; operation, outer-page, and domain continuation. |
| `search_assembly` | Search decompiled text or external calls/data access, returning declaration handles. | Assembly `targetPath`; `searchKind=text` (`external_calls`, `data_access`); optional `pattern`; `isRegex=null` auto-detects, `true` forces regex, `false` literal; `caseSensitive=false`, `declarationOnly=false`; optional `kind` (`method`, `type`, `property`) and `fileFilter`; `contextLines=0` (0–5); `maxResults=50` (zero also 50, max 1000); `maxFiles=0` (unlimited matched files, positive values capped at 2000); `detailLevel=standard`; bytes default 24,576 (zero also default); tokens and the shared operation/outer/domain paging values. |
| `find_assembly_extensions` | Find extension methods by receiver, name, or namespace. | Assembly `targetPath`; optional `receiverType`, `extensionName`, `namespace`; `includeReferences=false`; `maxResults=100` (zero also 100, max 1000); `detailLevel=standard`; bytes default 16,384 (zero also default); tokens and operation/outer-page tokens. An omitted receiver allows a broad search. |
| `get_feature_context` | Combine a source declaration, callers, and related static test candidates. | Source `targetPath`, required `symbolIdentifier`; source `scopeType=all`, `includeGenerated=false`; `maxCallers=10`, `maxTests=10` (1–50); operation/page tokens; bytes default 24,576. Text labels candidates `static-test-candidates-only`; it does not report measured test coverage or linter findings. |
| `get_test_context` | Find project-specific source test candidates for a symbol. | Source `targetPath`, required `symbolIdentifier`; source `scopeType=all`, `includeGenerated=false`; `maxResults=30` (1–100); operation/page tokens; bytes default 16,384. Name-only fixture matches remain heuristic and are labeled `Unknown`; this is not test-coverage measurement. |

## Practical patterns

Find a declaration and follow its handle to the body:

```json
{"name":"find_symbol","arguments":{"targetPath":"C:\\work\\App.slnx","pattern":"OrderService.Save","kind":"method"}}
{"name":"get_symbol_body","arguments":{"targetPath":"C:\\work\\App.slnx","symbolIdentifiers":["h:..."],"startLine":1,"maxBodyLines":80}}
```

For `RESPONSE_BUDGET_TOO_SMALL`, repeat the identical arguments and target with the exact byte/token minima from the error. For an outer text page, repeat the query with the response preamble's `continuationToken`. Do not mix these tokens or change filters while recovering a stored operation or page.

Inspect a large assembly with a small domain page, first consuming any outer pages for that response and then passing the opaque `resultCursor` back with unchanged filters. `continuationToken` is reserved for outer text pages; clients do not inspect cursor formats:

```json
{"name":"inspect_assembly","arguments":{"targetPath":"C:\\work\\bin\\Product.dll","maxResults":20}}
```

`inspect_assembly` returns type and member handoffs. Pass a type handoff to `get_file_skeleton` for its declaration-file outline or `get_class_structure` for its members; pass a type or member handoff to `get_symbol_body` for decompiled source. For physical source files and assets, use external file search. `get_index_scope` reports which solution documents participate in C# navigation.

Use `get_index_scope` on the solution path to see which C# projects/documents participate before choosing a source query. To change host logging, edit the startup settings file and restart the MCP process.
