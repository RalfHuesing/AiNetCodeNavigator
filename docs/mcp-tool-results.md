# MCP Tool Results

`McpToolResults` is an internal host utility for constructing `ModelContextProtocol.Protocol.CallToolResult` values. It emits exactly one text content block and sets `IsError` explicitly.

Repository-defined navigation labels, diagnostics, errors, and recovery hints use English. Tool names, protocol property names, and machine-readable error codes retain their existing values.

Successful text results use `Status: operation=ok, completeness=complete` and `IsError=false`; a shortened result uses `completeness=truncated` and retains its continuation hint. Navigation payloads carry typed `NavigationAnalysisMetadata` (`snapshotId`, normalized `analyzedScope`, `analysisCompleteness`, `resultContinuationAvailable`, and concrete `omissionReasons`), which the host shows in the status preamble. Analysis completeness is independent from outer response completeness. A domain cursor reports that another result page is available; concrete scanner or traversal limits report partial analysis with their reason. When navigation analysis metadata is available, the visible text preamble emits `resultContinuation=available` and concrete `omissions` when present; absence means no domain continuation and no omissions. The internal typed metadata retains its explicit values. Successful JSON text uses a compact projection with one newline per object property and array item, preserving pageable boundaries without indentation; JSON names and values are unchanged. The metadata fields are included in budget measurement and exact retry minima. An optional `JsonElement` can be attached as `StructuredContent` for an untruncated success. If the text projection is truncated or the domain result is incomplete, combining it with structured content is rejected to avoid presenting a partial text view beside an apparently complete structured result.

`Error`, `Recoverable`, and `InvalidArgument` all use `IsError=true`, an `[ERROR]` code, and an actionable `nextAction` when supplied. The status, code/message, argument path, budget recovery details, and correction action form a required envelope: it is emitted whole or rejected with `ArgumentOutOfRangeException` when the requested budgets cannot represent it. Optional context is added only when the required envelope still fits; it may be shortened or omitted to preserve those fields. Recoverability describes the recommended correction; it does not change the MCP error flag.

`Loading` is the transient exception: it uses `Status: operation=retry, completeness=not_applicable` and `IsError=false`. It accepts byte and token budgets and keeps the retry action as a required field. Its display message is shortened to at most 64 Unicode scalar values before formatting so it cannot displace the retry action. If the action itself cannot fit, the builder returns an `IsError=true` budget error when that error envelope fits; otherwise it throws rather than returning an over-budget response.

Budget failures use `Status: operation=error, completeness=not_applicable`, retain `RESPONSE_BUDGET_TOO_SMALL` recovery details, and set `IsError=true`. Success retry minima are selected from executable complete and truncated success projections: a full response is recommended when it fits the public byte ceiling with a lower complete-response budget; otherwise the truncated projection includes its final status prefix and continuation marker in the minimum. The error status and recovery envelope are formatted separately under the same byte and token limits. The error envelope is rechecked against its requested limits. Success, failure, loading, and budget-error status text is included in `McpResponseFormatter`'s UTF-8 byte and token accounting. An unrepresentable token cap is rejected instead of producing an over-budget result.

Completed source workspace load and reload failures are errors, never `Loading` controls. The response retains the error code, target, full exception text (including inner exceptions and stack traces), and a correction action. The host also writes the complete diagnostic at Error level through its configured file/stderr logging. An initial load failure is reported before another load attempt can replace its diagnostic; releasing the failed lease enables a fresh load on the next query. Retryability does not mean that loading is still in progress.

Workspace errors are stored in full before caller budgets are applied. If the complete error fits the public 65,536-byte ceiling but exceeds the requested byte or token budget, the operation store returns `RESPONSE_BUDGET_TOO_SMALL` with exact retry minima. Poll an existing operation token with those budgets, or repeat the query when no operation token was returned. If the full diagnostic exceeds the public byte ceiling, the response explicitly directs the caller to the complete server log instead of silently shortening the diagnostic or recommending an impossible response budget. See [Setup](setup/README.md#local-process-configuration) for the log location.

This is an internal construction layer. Tool registration and public stdio behavior are not established by it.
