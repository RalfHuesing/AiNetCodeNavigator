# MCP Host

The executable runs a Model Context Protocol server over stdio. Standard output is reserved for JSON-RPC messages; command-line help and parse errors go to standard error, and Serilog writes rolling files under `AppContext.BaseDirectory/logs` with error and fatal events mirrored to standard error. The host uses the .NET Generic Host and the SDK stdio transport. Runtime disposal drains owned operations, disposes source and assembly state, then clears process-local opaque handoffs. Disposal is idempotent so a repeated call cannot clear handles created by a fresh runtime.

The production host registers nineteen read-only navigation tools. The current handler contracts exercise original SDK definitions, validators, source and assembly owners, budgets, paging, and runtime handoffs without a client or transport. The maintained [tool reference](tools/README.md) describes the public catalog; the [setup guide](setup/README.md) describes supported local client configuration. Retained end-to-end host and handshake cases are excluded from the completion gates.

The host reads the optional JSON settings file at startup. Its only supported setting is `minimumLogLevel`, with exact values `Verbose`, `Debug`, `Information`, `Warning`, `Error`, or `Fatal`. The server does not watch or modify the file; restart the process to apply a change.

`get_index_scope` is source-only and accepts a byte budget of 512–65,536 with a default of 16,384, an optional positive token budget, and the shared `operationToken` and outer `continuationToken` fields. Those controls use the common host operation and response-page stores; budgets and tokens are excluded from the query identity. `CancellationToken` is an SDK-internal parameter and is not published in the tool schema. Its current SDK and cold-handler contract is covered by a transport-free test.

The full navigation catalog contains 17 tools: `find_symbol`, `get_symbol_body`, `get_file_skeleton`, `get_class_structure`, `get_namespace_tree`, `get_index_scope`, `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, `get_impact`, `dependency_graph`, `resolve_type_origin`, `get_context`, `inspect_assembly`, `search_assembly`, and `find_assembly_extensions`. Source symbol and structure calls route by an absolute `targetPath` to source solutions where their handler supports that target; assembly scanners use managed `.dll` and `.exe` targets. Use `get_index_scope` to check indexed source document coverage and external file search to discover physical files. For assembly discovery, use `inspect_assembly`, then pass type handoffs to `get_file_skeleton`, `get_class_structure`, or `get_symbol_body`. The [tool reference](tools/README.md) documents the implemented catalog and target differences.

`--config <path>` selects an explicit JSON file. Without it, the host reads `%LOCALAPPDATA%/AiNetCodeNavigator/hostsettings.json`; if that default file is absent, startup uses built-in `Information` logging. Unknown fields and malformed JSON are rejected during startup. See the [setup guide](setup/README.md) for the Windows command entry and client-specific configuration locations.

The repository retains real-process tests for MCP initialize/tool listing, stdio calls, EOF, and cold source solutions. They are `E2EIntegration` and are not current completion-gate evidence. The eligible read-only tests snapshot files and directories around source loading; MSBuild design-time scratch is isolated outside the workspace. Before opening a solution, the loader evaluates each project and rejects effective `IntermediateOutputPath`/`OutputPath` redirection outside its unique scratch directory; the controlled imported-target test confirms the target does not run and the failed load can recover after the redirection is removed. The loader does not provide a security sandbox for arbitrary executable MSBuild targets.
