# MCP Host

The executable runs a Model Context Protocol server over stdio. Standard output is reserved for JSON-RPC messages; command-line help and parse errors go to standard error, and Serilog writes rolling files under `AppContext.BaseDirectory/logs` with error and fatal events mirrored to standard error. The host uses the .NET Generic Host and the SDK stdio transport. Runtime disposal drains owned operations and disposes source and assembly state. Public declaration references are stateless values; assembly analysis still uses leased owner generations.

The production host registers 16 read-only navigation tools. Handler contracts exercise original SDK definitions, validators, source and assembly owners, budgets, paging, and stable declaration references without a client or transport. The maintained [tool reference](tools/README.md) describes the public catalog; the [setup guide](setup/README.md) describes supported local client configuration. Retained end-to-end host and handshake cases are excluded from the completion gates.

The MCP initialization metadata and the existing startup log identify the running build with the executable's informational version. The .NET build generates that value from the declared product version and, when source-control information is available, appends the source revision. Compare the value reported by the initialized server with the intended build before using it for a measurement. The version is emitted once at startup and in standard initialization metadata, not repeated in navigation results.

The host reads the optional JSON settings file at startup. `minimumLogLevel` accepts the exact values `Verbose`, `Debug`, `Information`, `Warning`, `Error`, or `Fatal`. Optional `trafficCapture` settings enable raw tool-call recording independently of the logging level; capture is disabled by default. The [setup guide](setup/README.md#local-process-configuration) documents all supported fields, defaults, and validation. The server does not watch or modify the file; restart the process to apply a change. See [MCP Traffic Capture](mcp-traffic-capture.md) for the captured files, measurement scope, and failure behavior.

`get_index_scope` is source-only and accepts a byte budget of 512–65,536 with a default of 16,384, an optional positive token budget, and the shared `operationToken` and outer `continuationToken` fields. Those controls use the common host operation and response-page stores; budgets and tokens are excluded from the query identity. `CancellationToken` is an SDK-internal parameter and is not published in the tool schema. Its current SDK and cold-handler contract is covered by a transport-free test.

The full navigation catalog contains 16 tools: `find_symbol`, `get_symbol_body`, `get_file_skeleton`, `get_class_structure`, `get_namespace_tree`, `get_index_scope`, `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, `dependency_graph`, `resolve_type_origin`, `get_context`, `inspect_assembly`, `search_assembly`, and `find_assembly_extensions`. Source symbol and structure calls route by an absolute `targetPath` to source solutions where their handler supports that target; assembly scanners use managed `.dll` and `.exe` targets. Use `get_index_scope` to check indexed source document coverage and external file search to discover physical files. For assembly discovery, use `inspect_assembly`, then pass type references with the exact reported owner target to `get_file_skeleton`, `get_class_structure`, or `get_symbol_body`. The [tool reference](tools/README.md) documents the implemented catalog and target differences; [Shared Symbol Resolution](navigation/symbol-resolution.md) documents reference semantics.

`--config <path>` selects an explicit JSON file. Without it, the host reads `%LOCALAPPDATA%/AiNetCodeNavigator/hostsettings.json`; if that default file is absent, startup uses built-in `Information` logging. Unknown fields and malformed JSON are rejected during startup. See the [setup guide](setup/README.md) for the Windows command entry and client-specific configuration locations.

The repository retains real-process tests for MCP initialize/tool listing, stdio calls, EOF, and cold source solutions. They are `E2EIntegration` and are not current completion-gate evidence. The eligible read-only tests snapshot files and directories around source loading; MSBuild design-time scratch is isolated outside the workspace. Before opening a solution, the loader evaluates each project and rejects effective `IntermediateOutputPath`/`OutputPath` redirection outside its unique scratch directory; the controlled imported-target test confirms the target does not run and the failed load can recover after the redirection is removed. The loader does not provide a security sandbox for arbitrary executable MSBuild targets.
