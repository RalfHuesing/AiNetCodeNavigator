# MCP Host

The executable runs a Model Context Protocol server over stdio. Standard output is reserved for JSON-RPC messages; command-line help and parse errors go to standard error, and Serilog writes rolling files under `AppContext.BaseDirectory/logs` with error and fatal events mirrored to standard error. The host uses the .NET Generic Host and the SDK stdio transport. End-of-input performs graceful shutdown; the host cancels active long-running operations, drains them, then disposes project and assembly resident state.

The production host registers two maintenance tools and all twenty navigation tools. Real stdio tests cover successful calls, one concrete invalid-input outcome per navigation tool, source and assembly handoffs, and the shared host validation contract. Tool-specific evidence and remaining boundaries are listed in [MCP navigation registrations](navigation/mcp-registration-status.md) and the [public host and tool contract matrix](../tasks/Navigator-Migration/Reviews/public-contract-matrix.md). These implementation tests do not replace the independent 8.5/9.2/9.3/9.4 audits.

- `get_server_health` reports process uptime, resident source and assembly sessions, active assembly accesses, handoff count, compilation-cache counters, settings version, minimum log level, and managed memory. An optional `targetPath` reports whether an existing supported solution or assembly is already resident. The check reads registry metadata only; it does not load or refresh a target. It does not return compiler or assembly diagnostic samples. Health is returned as a complete snapshot; if the requested budget cannot hold it, the tool returns a retry budget when that recovery fits, otherwise a sanitized `InvalidParams` error when even the recovery envelope cannot fit.
- `reload_config` reloads the active JSON settings file. The only currently supported runtime setting is `minimumLogLevel`, with exact values `Verbose`, `Debug`, `Information`, `Warning`, `Error`, or `Fatal`. A valid changed value publishes a new immutable version and changes the Serilog level switch; an unchanged value keeps the current version. The complete acknowledgement is checked before publication, so an undersized response budget does not change settings. Invalid, unreadable, or missing files also leave the active version and log level unchanged.

Both tools accept `maxResponseBytes` (512–65,536; default 16,384) and optional `maxResponseTokens` (positive integer). These limits apply to successful and recoverable error results. A token limit too small to represent the required result is returned as a sanitized `InvalidParams` error.

The full navigation catalog is `find_symbol`, `get_symbol_body`, `get_file_skeleton`, `get_class_structure`, `get_file_tree`, `get_namespace_tree`, `get_index_scope`, `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, `get_impact`, `dependency_graph`, `resolve_type_origin`, `get_assembly_context`, `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, `get_feature_context`, and `get_test_context`. Source symbol and structure calls route by an absolute `targetPath` to source solutions where their handler supports that target; assembly scanners use managed `.dll` and `.exe` targets. Assembly symbol handoffs retain their target identity and the tested body follow-up remains available. Stdio fixtures cover every registered navigation tool with success and a tool-specific invalid-input result, including `.git`-file worktree Git changes, assembly-reference closure, response-page recovery, and exact large-result reconstruction. Host lifecycle tests cover parallel requests, a canceled polling waiter while its shared operation continues, shutdown of a live Git child, restart isolation of old handoffs, clean EOF, and protocol-only stdout. Full per-field/default/cap parity and exact byte/token recovery for every tool remain open.

`--config <path>` selects an explicit JSON file. Without it, the host reads `%LOCALAPPDATA%/AiNetCodeNavigator/hostsettings.json`; if that default file is absent, startup uses built-in `Information` logging. Calling `reload_config` when no default file exists returns `CONFIG_NOT_FOUND`. Unknown fields and malformed JSON are rejected. The host does not watch the file automatically and never writes it.

Real-process integration tests perform MCP initialize/tool listing, exercise source and managed-assembly handoffs, all current navigation registrations, and cold source solutions. Cold tests snapshot files and directories before the first navigation call and after host termination; the two-solution test includes same-named projects. MSBuild design-time scratch is isolated outside the workspace. Arbitrary custom MSBuild target redirection remains unverified.
