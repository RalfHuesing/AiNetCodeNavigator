# MCP Host

The executable runs a Model Context Protocol server over stdio. Standard output is reserved for JSON-RPC messages; command-line help and parse errors go to standard error, and Serilog writes rolling files under `AppContext.BaseDirectory/logs` with error and fatal events mirrored to standard error. The host uses the .NET Generic Host and the SDK stdio transport. Runtime disposal drains owned operations, disposes source and assembly state, then clears process-local opaque handoffs. Disposal is idempotent so a repeated call cannot clear handles created by a fresh runtime.

The production host registers two maintenance tools and nineteen navigation tools. The current handler contracts exercise original SDK definitions, validators, source and assembly owners, budgets, paging, and runtime handoffs without a client or transport. The maintained [tool reference](tools/README.md) describes all 21 public tools; the [setup guide](setup/README.md) describes supported local client configuration. Retained end-to-end host and handshake cases are excluded from the completion gates.

- `get_server_health` reports process uptime, resident source and assembly sessions, active assembly accesses, handoff count, compilation-cache counters, settings version, minimum log level, and managed memory. An optional `targetPath` reports whether an existing supported solution or assembly is already resident. The check reads registry metadata only; it does not load or refresh a target. It does not return compiler or assembly diagnostic samples. Health is returned as a complete snapshot; if the requested budget cannot hold it, the tool returns a retry budget when that recovery fits, otherwise a sanitized `InvalidParams` error when even the recovery envelope cannot fit.
- `reload_config` reloads the active JSON settings file. The only currently supported runtime setting is `minimumLogLevel`, with exact values `Verbose`, `Debug`, `Information`, `Warning`, `Error`, or `Fatal`. A valid changed value publishes a new immutable version and changes the Serilog level switch; an unchanged value keeps the current version. The complete acknowledgement is checked before publication, so an undersized response budget does not change settings. Invalid, unreadable, or missing files also leave the active version and log level unchanged.

Both tools accept `maxResponseBytes` (512–65,536; default 16,384) and optional `maxResponseTokens` (positive integer). These limits apply to successful and recoverable error results. A token limit too small to represent the required result is returned as a sanitized `InvalidParams` error.

`get_index_scope` is source-only and accepts the same byte range with a default of 16,384, an optional positive token budget, and the shared `operationToken` and outer `continuationToken` fields. Those controls use the common host operation and response-page stores; budgets and tokens are excluded from the query identity. `CancellationToken` is an SDK-internal parameter and is not published in the tool schema. Its current SDK and cold-handler contract is covered by a transport-free test.

The full navigation catalog is `find_symbol`, `get_symbol_body`, `get_file_skeleton`, `get_class_structure`, `get_namespace_tree`, `get_index_scope`, `get_call_tree`, `find_references`, `get_type_hierarchy`, `find_implementations`, `get_impact`, `dependency_graph`, `resolve_type_origin`, `get_assembly_context`, `inspect_assembly`, `search_assembly`, `find_assembly_extensions`, `get_feature_context`, and `get_test_context`. Source symbol and structure calls route by an absolute `targetPath` to source solutions where their handler supports that target; assembly scanners use managed `.dll` and `.exe` targets. Use `get_index_scope` to check indexed source document coverage and external file search to discover physical files. For assembly discovery, use `inspect_assembly`, then pass type handoffs to `get_file_skeleton`, `get_class_structure`, or `get_symbol_body`. Earlier stdio fixtures for tool calls and invalid inputs remain retained tests, but their assertions are historical evidence and are excluded from the current completion gates. The [tool reference](tools/README.md) documents the implemented 21-tool surface and target differences.

`--config <path>` selects an explicit JSON file. Without it, the host reads `%LOCALAPPDATA%/AiNetCodeNavigator/hostsettings.json`; if that default file is absent, startup uses built-in `Information` logging. Calling `reload_config` when no default file exists returns `CONFIG_NOT_FOUND`. Unknown fields and malformed JSON are rejected. The host does not watch the file automatically and never writes it. See the [setup guide](setup/README.md) for the Windows command entry and client-specific configuration locations.

The repository retains real-process tests for MCP initialize/tool listing, stdio calls, EOF, and cold source solutions. They are `E2EIntegration` and are not current completion-gate evidence. The eligible read-only tests snapshot files and directories around source loading; MSBuild design-time scratch is isolated outside the workspace. Before opening a solution, the loader evaluates each project and rejects effective `IntermediateOutputPath`/`OutputPath` redirection outside its unique scratch directory; the controlled imported-target test confirms the target does not run and the failed load can recover after the redirection is removed. The loader does not provide a security sandbox for arbitrary executable MSBuild targets.
